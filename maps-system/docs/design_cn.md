# 设计：Google Maps 参考实现

## 带版本的图与空间数据
SQLite WAL 保存规范化的节点/边/地址，SQLite RTree 保存边的包围盒、交通、用户、位置事件与配置。原子导入构建一张新图，随后在同一事务中交换图 UUID 和目录版本号。旧的读取方继续使用各自的快照。图缓存键包含图 UUID；交通权重在同一读事务中读取，因此单条路径不会混用不同版本。邻接关系按源节点所在的 XYZ 路由瓦片（z=16）分组，包含指向其他瓦片目标节点的引用。有界 LRU 仅加载搜索触及的瓦片。这是分区的惰性路由，而非层次收缩（Contraction Hierarchies）或全局 A*。

## 路径规划与 ETA
Dijkstra 算法最小化非负的通行时间。每条边、每种模式各自拥有以米每秒为单位的速度；实时驾驶的覆盖/封路会过期。基线模型为长度/速度，不考虑转弯惩罚、信号灯、定期公共交通或已学习的交通预测。候选路径以避开最优路径中的一条边重新运行最短路径，去重后对结果排序。这一有界启发式并非完整的 K 最短路径算法。显式的 `/route` 请求会重新计算一条全新的路径用于重规划。地址解析使用严格的规范化（casefold）固定数据集查找；坐标起终点采用有界的最近节点吸附。

## 位置/交通流水线
所有者凭据在本地配置并以哈希形式存储。每批最多 100 条上报。每个（用户，事件 ID）保存载荷哈希与处理结果；同一 ID 下不同载荷视为冲突。整批要么提交要么回滚。被接受的序列号/时间戳对单调推进当前位置；迟到事件留在保留历史中但不会改变当前交通采样状态。最近路段匹配使用局部切平面近似（最大 100 米），而非 HMM 地图匹配。航向用于选择有向边，且必须在 60 度内一致；缺失或歧义的航向仍会保存上报，但无法产出速度采样。只有在同一条有向边上前进的比例递增才会生成速度采样；不现实的速度与过大的时间间隔会被拒绝。不同用户加上 5 分钟窗口共同作为平均速度交通更新的门禁条件。手动的管理员交通操作和显式的聚合操作都会推动目录版本号。这条 SQL 流水线替代了 Kafka/Cassandra，作为本地参考实现；不宣称存在模拟的 Kafka 部署。

## 瓦片与网络角色
WGS84 投影到 XYZ Web Mercator，极地处做钳制。归一化投影坐标下的线段裁剪处理共享边与 180° 经线展开。GeoJSON 保留地理坐标；PNG 使用标准库的线段光栅化器与 zlib PNG 编码器。两者都来自同一批被裁剪的线段。URL 包含图 UUID、z/x/y 与格式，内容附带 ETag 与不可变缓存头。旧来源图的 URL 在替换后返回 410；现有 CDN 副本会保持有效，因为一个 UUID URL 上的内容永不改变。不部署 CDN。

主节点负责图导入、上报与交通。独立的只读副本拉取经过身份验证的完整公开目录（图、地址、活跃交通）到独立的 SQLite 文件中。安装是原子性的；沿袭/版本校验拒绝回滚或未知来源。私有位置/身份表被排除。规范化的 SHA-256 图校验和拒绝现有 UUID 下被改动的道路，并在副本之间保持导入数据集的许可证。网关将公开的地理编码/路径/瓦片读取转发到配置好的同区域对等节点，对传输错误和 5xx 错误重试。副本在主节点不可用时继续服务上一个完整快照。快照的陈旧程度可在健康/路径结果中看到。本地区域配置不是地理部署；全量复制不是增量数据库复制或主故障转移。

## 范围边界
包围盒使用 RTree 筛选候选；在短段上精确匹配是近似的。合成道路用于确定性的工程测试，而非真实出行。不保证导航安全与道路完备性。生产环境需要经授权的道路数据源、转弯限制、层次化路由、准确的地图匹配、预测模型、可扩展的流/历史系统、HTTPS、身份认证、区域本地存储、高可用、备份、地图样式/字体以及真实的负载/运维验证。保留策略在查询时逻辑生效，同时在活跃期间进行机会性的物理清理。

# 第8章测量记录 — 2026-10-31

环境：Windows11 10.0.26100，Python3.13.9，SystemClock，零运行时依赖。
基线为本轮改动前的唯一ID源码；前后使用同一解释器、同一脚本、相同参数。
与测试/图构建分开执行，但未隔离CPU频率、调度和共享主机后台负载。

## 测试与示例

基线94项/1.14秒；新增28项用例在旧实现26项失败、2项通过；最终122项/1.22秒，
警告按错误处理，无跳过或警告过滤。测试用时不是性能结论。
`examples/basic_usage.py`、`examples/multi_generator.py`均运行成功。

## 发号基准

```sh
python tools/benchmark.py --count 100000 --clients 4 --repeats 3 --output benchmarks/local.json
```

每个场景/样本100000个ID；下面前三行均为3次样本吞吐的中位数。

| 场景 | 修改前 ID/s | 本轮 ID/s | 条件 |
|---|---:|---:|---|
| 单线程逐ID | 523136.77 | 858352.89 | 每次generate取得实例锁 |
| 单线程批量 | 636278.03 | 1138456.84 | 每批最多1000，整批一次持锁 |
| 共享实例4线程 | 530136.96 | 866646.50 | 每线程25000次generate，包含线程池创建/回收 |
| 4个独立进程 | 259076.55 | 365390.64 | 各25000，机器ID为0..3；单次测量，含启动、IPC和回收 |

计时包含ID列表构建，范围/顺序/去重校验在计时结束后；进程场景传回完整ID列表
再统一去重。每个样本独立校验，不将不同样本复用身份后的结果混作一个ID空间。
单线程样本均超过原书10000 ID/s目标；不能由吞吐均值推断逐请求p99或服务SLA。

前后观察到吞吐提高，与将冻结掩码/位移/前缀移出发号路径一致，但只有一次
前后对照、各3个短样本，不能承诺所有环境都有相同提升，更不能把线程安全解释
成多线程线性加速。多进程验证使用4个不同PID，证明的是本次不同身份输出无重复，
未实现身份分配/租约、共享生成器跨进程安全、崩溃重启或时钟分区演练。

# 第 08 章原书核对

原书最终选择 Snowflake；多主数据库、UUID 和 Ticket Server 是比较后放弃的方案，并非要求同时部署的服务。

| 章节内容 | 当前实现 |
| --- | --- |
| 数值型、64 位 ID | 默认 1 位符号位固定为 0，41 位时间、5 位数据中心、5 位机器、12 位序列；配置总有效位固定 63。 |
| 自定义 epoch、时间排序 | 支持自定义 epoch，默认 2024-01-01，与书中 Twitter epoch 不同；越界拒绝生成。单实例按时间递增，跨机器只能在时钟同步假设下按时间近似排序。 |
| 固定节点身份 | 不可变 SnowflakeConfig；严格拒绝 bool、小数、字符串配置。不同进程/实例必须分配不同 (datacenter_id, machine_id)。 |
| 同毫秒序列耗尽 | 等待下一毫秒，每次睡眠让出 CPU；使用单调时钟限制等待期限，默认 1 秒。超时抛 SequenceOverflowError；等待期间发生回拨立即抛 ClockMovedBackwardsError。失败不覆盖上一次成功状态。 |
| 并发 | 单实例用互斥锁保护时间戳和序列；批量生成一次持锁，减少锁开销。长批量会延迟其他调用，业务应限制批量大小。 |
| 位数调整和解析 | 可配置位分配并反向解析；生成器与解析器必须使用同一配置。 |
| 替代方案 | UUIDGenerator 已实现 UUID；多主固定步长和集中 Ticket Server 是书中的方案比较，不声称已部署数据库复制或票号服务。TimestampRandomGenerator 是额外示例，不具有严格唯一性保证。 |

## 使用和运行边界

`SnowflakeGenerator(config, clock, overflow_timeout_seconds=1.0)` 支持配置等待期限；0 表示耗尽时立即失败。只在容量耗尽时检查超时，不改变正常生成路径。批量失败之前产生的 ID 已被消耗，批量生成不提供事务回滚。

线程安全只覆盖同一个生成器实例。复用相同节点身份的多个实例、进程或重启实例可能生成重复 ID；本项目未实现分布式身份租约、持久化时间戳高水位或重启隔离。部署时必须保证身份唯一，并确保重启后的时间超过该身份最后成功生成 ID 的毫秒。不能把 MonotonicClock 当作跨进程的身份/时钟协调服务。

原书将时钟同步的实现明确放在范围之外；这里对回拨拒绝发号，不自动修正系统时间。高可用性仍依赖部署多个不同身份的生成器，未提供协调服务故障转移。4096 ID/ms 是位分配容量，不是经过压测的吞吐承诺；原书的 10,000 ID/s 应在目标环境另行压测。

## 本轮验证

新增行为回归覆盖：无效配置类型、时钟停滞超时后继续发号、等待期间回拨、16 批请求共享线程安全序列。完整项目测试结果记录于仓库 DEEP_REVIEW_PROGRESS.md。

完整测试：94 passed；Ruff E9/F 通过。本机单线程生成 100,000 个 ID 用时 0.4861 秒，全部唯一，约 205,710 ID/s。这是单次本机测量，不代表部署后的持续吞吐。

## 本轮变更

1. 冻结配置允许构造时计算`_max_sequence`、`_max_timestamp`、`_timestamp_shift`
   和`_node_prefix`。逐ID避免重复计算掩码、位移及机器字段；时间/序列仍在同一
   锁内先校验、后提交，不新增缓存ID、后台线程或跨实例共享状态。
2. 解析此前将整数毫秒除成浮点秒，3000年的`.123000`会变成`.123001`；本机
   Windows转换9999年日期还会抛OSError。现用UTC Unix起点加整数毫秒timedelta，
   精确保留毫秒并避开系统timestamp转换限制。超出Python日期范围统一抛ValueError。
3. 解析拒绝bool、浮点、字符串等非整数；备用批量接口与Snowflake统一要求正整数
   count。时间戳-随机策略拒绝不合法epoch、起点前的时间和超过42位的偏移，避免
   返回负数或超过64位的结果；仍明确保留其概率碰撞语义。
4. 修正示例与异常说明；双语设计文档将六段重复实现替换为源码链接，保留架构、
   职责和权衡，并更新README、需求、任务、源码学习路线及根索引。

## 兼容性与部署条件

正常Snowflake输出布局、epoch和公共方法保持不变。新增的严格校验会使以前被
接受的bool解析、空/负数批量，以及不合法的备用策略epoch改为ValueError；
其他非整数输入也统一为ValueError。UTC表示更精确，日期越界不再暴露平台差异异常。
Snowflake只占有符号64位的非负范围；时间戳-随机允许完整无符号64位，存储类型须匹配。

同一节点身份不能由多个独立实例同时使用。重启后应确保时钟超过该身份最后成功
生成ID的毫秒，或者使用部署方提供的隔离/租约/高水位机制。MonotonicClock只在
本对象生命周期内避免回拨，不同步机器、不同步多个实例，也不保护重启身份重用。
跨机器或更换配置后的ID不保证全局严格递增，批量失败不回滚已消耗状态。

## 验证

- 基线94项/1.14秒；新增28项用例在旧实现26项失败、2个合法时间边界通过；
  最终**122项/1.22秒**，`-W error`，无跳过或警告过滤。
- [边界回归](../tests/test_open_source_review.py)覆盖输入类型、3000/9999年毫秒精度、
  不可表示日期、随机策略前后时间边界及批量参数。既有回拨、序列超时、属性测试和
  8线程/16批次共享实例验证继续通过。
- 两个示例通过；[基准工具](../tools/benchmark.py)使用真实SystemClock，逐样本校验
  范围、每线程/批次顺序和唯一性；4个独立PID使用不同机器ID，共生成100000条并校验。
- 性能、主机条件、计时范围和限制见[测量报告](../benchmarks/REPORT.md)，不把
  短时发号能力等同于生产环境的高可用性。

UUID比较表同时修正了概率表达：UUID v4有122个随机位，见
[RFC 9562第5.4节](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.4)。独立均匀随机
假设下，一对UUID碰撞概率为2^-122；本地22位随机后缀在同毫秒的一对碰撞概率
为2^-22，不能将其说成整个毫秒窗口内任意数量请求的总碰撞概率。

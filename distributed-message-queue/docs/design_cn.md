# 设计：分布式消息队列

## 角色、职责和并发

单个持久化HTTP协调器拥有主题元数据、分区epoch/高水位、生产者回执、消费者租约/
游标和事务可见性。独立broker各自拥有磁盘；所有用户操作经过协调器。不能把多个
进程共享元数据数据库当作共识或故障切换。

协调器保留公开facade，拆出复制、组、保留、校验和操作锁。128个有序固定RLock
条带保护分区的探测/复制/发布协议；不同条带可推进，碰撞仍串行。跨资源事务统一
顺序取得源/目标、生产者/事务锁；同producer ID跨分区也串行，以隔离epoch变化，
不同ID可在不同分区资源上推进。网络不持元数据事务；发布、成员资格复查使用短
SQLite WAL事务，元数据写者仍只有一个。

每个PartitionLog的RLock保护读、追加、同步、保留和换代；broker注册锁只保护加载
所有权和发布。Future合并同一分区并发打开，另一分区的磁盘校验不占全局I/O锁。

## 日志、校验和恢复

帧包含magic、有界长度、CRC32和规范JSON信封：offset、时间戳、生产者、文本/key/
tags、到期时间、前哈希及SHA-256链哈希。offset/位置旁车索引从已验证帧重建，正文
按需读取。不完整活动尾部可截断，完整CRC/哈希损坏失败关闭；空尾段不意味着前段
损坏可以丢弃。

整批输入先冻结、验证，再截断暂存尾部或触碰数据文件。同段相邻帧合并写入，每批
每个触及的数据/索引文件各flush/fsync一次。I/O失败将当前日志对象标为不可继续
使用，避免以不确定内存状态确认。epoch/base检查点和代指针用原子替换；平台支持
时尝试目录fsync。已验证的是进程故障，不能推断所有Windows文件系统/控制器掉电
保证。

帧、批次、读取和快照有显式预算。慢副本可能需要先保留清理才能让快照适配安装
上限；不是无限流式追赶。索引元数据仍随保留offset数量增长。

## 发布与复制

协调器在网络写前持久暂存每分区一个pending批次。leader/follower对齐已提交前缀，
追加相同规范记录；确认的offset/hash和消费者读取页都与元数据校验。落后副本把
完整保留前缀安装到新代，再原子切换指针。追赶是有界全量快照，不是增量/分块流。

选主在已提交高水位探测哈希，只允许合格副本成为leader。epoch递增隔离旧请求，
错误同步在破坏原暂存后缀前拒绝。任何用户可见发布由元数据拥有者决定，隔离的
broker不能自行提交用户写入。

默认all确认需配置broker多数，回执列实际确认节点。这是每操作追上的集合，不是
Kafka完整ISR/min.insync.replicas协议。失去quorum保留不确定pending，必须用同
sequence/同内容重试。leader确认返回committed=false，后台达到quorum前不可读。
协调器pending是额外的单磁盘副本，没有复制。

## 生产者客户端

序列按epoch/topic/partition维护，固定条带串行化序列协议；排队/重试前复制消息。
不确定发送保留原批并拒绝替换，retry_pending重发这份内存内容。新epoch隔离旧
客户端，但不跨进程/epoch防重复。

send发送一个分区批次；send_many按key路由分组（无key随机），保留分区内输入
顺序，回执附input_indexes。前批可能成功而后批失败，并非跨分区原子发送。

BufferedProducer拥有一个线程和有界消息队列，batch size/linger在延迟与RPC/fsync
摊销间取舍。submit返回Future，发出前取消可省略记录；发出后取消不能撤销写入。
flush/close等待接受的工作；工作线程回调不能同步join自身，先关buffer再关Client。

fire_and_forget使用有界执行器，只发一次leader确认请求、不自动重试，Future报告
错误。Client.close停止接收并排空已接收的同步/异步调用。未实现持久客户端spool，
不保证进程退出时投递。

## 消费、过滤、事务和扩容

成员使用租约，按排序ID轮询分配。加入/替换/退出/过期改变generation并使投递边界
失效。commit检查会话、代次、所有者、租约和已扫描投递边界；broker I/O后复查成员。
至少一次显式commit才推进；至多一次响应前落盘游标，可能丢失。

标签按OR命中，limit限制扫描输入而非命中输出，空页也可能跨非匹配记录推进
next_offset。提交后换过滤条件需reset才能找回跳过记录。delay_seconds与deliver_at
互斥；未到期队首阻塞后续，保持分区顺序，调度不延长保留时间。长轮询等待不占分区/SQL锁；wait_seconds
限制等待阶段，不强制打断已接收RPC。

事务先暂存/复制全部输出，再用一个SQLite事务推进输出高水位和输入游标；
txid/指纹去重。崩溃恢复中止未完成事务阶段并保持不可见，暂存后缀使用前修复。
恰好一次仅限队列可见性与游标，不含外部副作用、新txid或显式reset。

增大分区数创建空分区、提高所有组generation，旧日志不搬迁。分区数改变使取模键
路由改变，应用负责迁移期顺序。未实现缩容、动态broker或旧数据自动重新分布。

## 保留、传输和运维

默认14天或每分区8MiB信封数据先到者生效。floor/哈希检查点只跨已提交记录推进；
物理删除完整旧段，失败按broker记录持久重试。过期offset返回410，不静默跳过。
旧回执可过期，序列水位阻止旧sequence重生；epoch/事务回执GC仍不完整。

HTTP默认32个handler、128监听队列、10秒绝对socket截止和32MiB正文/响应上限。
正文前鉴权，严格framing、重复JSON字段及非有限数检查。直接RPC不走环境代理/
重定向，HTTPS保持正常证书校验。socket预算不能强杀DNS/SQLite/CPU，工作实际退出
前继续占容量。关闭取消请求I/O并join已接收handler，再排空非daemon维护线程。
维护失败使用不带敏感正文的日志，maintenance_error公开重试状态。

本地归档/回放最多100000条/64MiB并生成新offset，不是云分层或事务恢复。最终
执行与测量见[验证报告](../benchmarks/results.md)，原书映射见[章节记录](chapter20-review.md)。
共识/故障切换、动态放置、增量追赶、zero-copy、TLS/ACL/配额、元数据GC、云备份/
分层、跨地域恢复和持续负载/混沌验收仍待扩展。

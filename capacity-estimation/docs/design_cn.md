# 第3章 —— 显式假设的估算模型

本地源章节介绍了 2 的幂、操作延迟、可用性预算以及一个假想的社交网络工作负载。可执行的范围是单位安全的算术运算、透明的假设与敏感性分析。它不会获取当前的云服务商 SLA，不会推荐硬件，也不会把历史延迟常数当作实测事实。

在本地 80 位有效数字的 Decimal 上下文中使用 Decimal。Decimal 输入是字符串/整数（或在 Python API 中为 Decimal），绝不是二进制浮点数。CLI JSON 中的数值小数被解析为字符串。输入必须是有限的，在数量级/长度/指数上受限，并经过语义校验。输出保留十进制字符串；产生循环小数的除法受精度限制。单位解析区分大小写，字节值必须能够解析为整数字节。DecimalMB 与 binaryMiB 被刻意区分。

设 M=MAU（月活用户数）、d=日活比例、w/r=每个 DAU 的写/读次数、p=峰值倍数、T=保留天数、R=副本数、c=压缩比、i=索引开销、h=热数据比例、s=缓存条目大小：

| 结果 | 公式 / 单位 |
|---|---|
| DAU | M×d，估算用户数 |
| 每日写/读操作 | DAU×w / DAU×r，次/天 |
| 平均 QPS | 每日操作数÷86400 |
| 峰值 QPS | 平均 QPS×p |
| 平均写字节数 | 元数据字节 + 媒体占比×媒体字节 |
| 每日逻辑字节 | 每日写操作×平均写字节数 |
| 保留逻辑字节 | 每日逻辑字节×T |
| 物理字节 | 保留逻辑字节×c×R×(1+i) |
| 缓存字节 | 每日写操作×T×h×s |
| 平均入口比特/秒 | 每日逻辑字节×8÷86400 |
| 平均出口比特/秒 | 每日读操作×读响应字节×8÷86400 |
| 峰值带宽 | 平均带宽×p |
| 服务节点数 | ceil(峰值总 QPS×安全系数÷(节点 QPS×利用率)) |
| 总节点数 | 服务节点数 + 显式备用节点数 |
| 峰值在途请求估计 | 峰值总 QPS×假设的平均延迟（秒） |
| 停机秒数 | 周期秒数×(1−可用性百分比÷100) |

月/年时长按 30/365 天计算。在需求为零时，服务节点数可以为 0，而配置的备用节点仍然保留。比例被限制在 [0,1] 区间，压缩比/利用率必须严格为正，峰值/安全系数≥1，需要离散单位的计数必须是整数。极端的零指数同样会在格式化之前被拒绝，以防止生成巨大的字符串。

缓存比例（cache fraction）指所有保留写记录中的一个比例，而不是命中率；不会据此推断出读 QPS 的降低。索引开销建模在每个压缩副本之上。网络流量不包含协议/安全开销、重试、复制以及缓存流量。节点 QPS 是外部提供的混合工作负载假设；延迟指平均响应时间。这些区分防止把算术运算呈现为一个独立的系统模型。

敏感性分析为同一个输入场景创建独立的副本，仅替换白名单中的字段，最多 20 个场景。它不优化参数，也不暗示确定性。这里没有实时价格、过时的硬件表或第三方服务。

九项测试检查参考算术、十进制/二进制转换、压缩/索引/副本的应用顺序、带宽比特数、节点上限、利特尔定律（Little's law）、可用性边界、无效输入、敏感性单调性以及真实的 CLI 进程。命令与保存的输出见 `../benchmarks/REPORT.md`。生产环境的容量规划仍然需要实测的工作负载、瓶颈识别、增长分布、冗余/故障域以及运维层面的 SLO 定义。

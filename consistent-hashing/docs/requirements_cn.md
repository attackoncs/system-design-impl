# 需求：一致性哈希（Consistent Hashing）

## 概述

一个 Python 一致性哈希（Consistent Hashing）库，实现带虚拟节点（Virtual Node）的哈希环（Hash Ring）算法，使键在各服务器之间均衡分布。支持服务器的动态添加/移除，且只需迁移最少的键，适用于缓存、数据库和负载均衡器等分布式系统。

## 功能需求

### FR-1: 哈希环核心

- **FR-1.1**：默认SHA-1完整160位，MD5/SHA-256分别128/256位；自定义函数返回严格整数位置，不自动取模。
- **FR-1.2**：系统应通过对服务器节点标识符（如 "server-1"、"192.168.1.1:8080"）进行哈希，将其映射到哈希环上的位置。
- **FR-1.3**：系统应通过对键字符串进行哈希，将键映射到哈希环上的位置。
- **FR-1.4**：系统应通过从键的位置开始沿顺时针遍历，直到找到第一个服务器节点，来完成键到服务器的查找。
- **FR-1.5**：如果从键的位置顺时针方向上不存在服务器节点（即键已越过环上最后一个服务器），系统应回绕（wrap around）到环上的第一个服务器节点。

### FR-2: 虚拟节点（Virtual Node）

- **FR-2.1**：系统应支持虚拟节点（副本），即每个物理服务器由哈希环上的多个位置表示。
- **FR-2.2**：每台服务器的虚拟节点数量应可配置（默认：150）。
- **FR-2.3**：虚拟节点的位置应通过对服务器标识符的变体进行哈希来生成（如 "server-1#0"、"server-1#1"、……、"server-1#149"）。
- **FR-2.4**：键查找应将虚拟节点与物理节点同等对待——顺时针找到的第一个虚拟节点映射回其所属的物理服务器。
- **FR-2.5**：系统应允许按服务器设置虚拟节点数量（加权节点），为容量更大的服务器分配更多的环空间。

### FR-3: 服务器管理

- **FR-3.1**：系统应支持在运行时向环中添加服务器，将其虚拟节点放置到环上，并且只重新分配受影响的键。
- **FR-3.2**：系统应支持在运行时从环中移除服务器，移除其虚拟节点，并且只将受影响的键重新分配给下一个顺时针服务器。
- **FR-3.3**：添加一台拥有 N 个虚拟节点的服务器，应只影响落在新增虚拟节点位置与其在环上前一个节点之间的键。
- **FR-3.4**：移除一台服务器应只影响原本分配给该服务器的键——这些键移动到下一个顺时针服务器。
- **FR-3.5**：系统应提供一种方法，用于查询在添加或移除服务器时哪些键会被重新分配。

### FR-4: 键分布与查找

- **FR-4.1**：系统应提供 `get_node(key)` 方法，返回负责给定键的服务器。
- **FR-4.2**：系统应提供 `get_nodes(key, count)` 方法，为一个键返回多个不同的服务器（用于副本/replication），沿顺时针遍历并跳过重复的物理服务器。
- **FR-4.3**：系统应提供一种方法，检索分配给特定服务器的所有键。
- **FR-4.4**：系统应提供关于键在各服务器上分布情况的统计信息（每台服务器的数量、标准差、最小/最大值）。

### FR-5: 配置

- **FR-5.1**：哈希函数应可配置（默认 SHA-1，支持 MD5、SHA-256 或自定义哈希函数）。
- **FR-5.2**：虚拟节点数量应可在创建哈希环时配置，也可按服务器配置。
- **FR-5.3**：系统应接受字符串形式的服务器标识符（主机名、IP:port 或任意标签）。

### FR-6: 演示

- **FR-6.1**：系统应包含一个示例脚本，演示哈希环的创建、键的分配、服务器的添加/移除以及由此产生的键重新分配。
- **FR-6.2**：示例应打印统计信息，展示拓扑变更前后的分布均衡情况。
- **FR-6.3**：示例应可视化或报告在添加或移除服务器时哪些键发生了移动。

## 非功能需求

### NFR-1: 性能

- **NFR-1.1**：键查找（`get_node`）应使用二分查找在 O(log N) 时间内完成，其中 N 为环上虚拟节点总数。
- **NFR-1.2**：采用不可变快照及复制发布；如实列出批量排序、变更与规划成本，不要求不适用的O(K log N)。
- **NFR-1.3**：验证10000及50000条目并记录耗时/内存，不承诺随规模增长完全无退化。

### NFR-2: 正确性

- **NFR-2.1**：对于稳定的哈希环（无拓扑变更），同一个键应始终映射到同一台服务器（确定性）。
- **NFR-2.2**：验证增节点只迁向新节点，删节点只迁走原owner；均匀等权下的平均比例是期望而非硬上限。
- **NFR-2.3**：报告有限样本的均衡指标及内存权衡，不保证所有输入CV<=20%或随虚拟节点数单调改善。

### NFR-3: 测试

- **NFR-3.1**：项目应包含使用 pytest 编写的单元测试，覆盖所有公开方法。
- **NFR-3.2**：项目应包含使用 Hypothesis 的基于属性的测试（property-based test），验证正确性不变量（确定性、最小化数据迁移、均衡分布）。
- **NFR-3.3**：测试应验证服务器添加/移除时的键重新分配是有界的且最小的。

### NFR-4: 项目结构

- **NFR-4.1**：项目应遵循与 rate-limiter 模块相同的结构（pyproject.toml、src 布局、tests、examples、docs）。
- **NFR-4.2**：项目应使用标准的 Python 打包方式与 hatchling。
- **NFR-4.3**：项目应全程使用类型注解（type hints）。
- **NFR-4.4**：项目应提供 README，包含使用说明和算法讲解。

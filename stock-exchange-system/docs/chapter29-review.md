# 第29章证券交易所：启动重放效率（2026-11-09）

原书Event sourcing一节要求以快照和重放快速恢复状态。旧`Engine._rebuild`对完整日志重放三遍：先全量重放，有快照时再重放前缀做兼容比对，最后又全量重放一遍以重建行情增量窗口；且`reduce_command`每条命令深拷贝整个状态（订单/成交随历史增长），重放为平方级。1000条命令上限时，带快照重启实测约8.3秒。

- 新增原地`apply_command`，`reduce_command`保持纯函数（拷贝后调用前者）。引擎重放、定序器启动去重索引核对和主备提升的独立重放均改用原地折叠。
- `_rebuild`改为单次线性遍历：链只校验一次；遍历到快照序号时用原`compatible`比较（旧格式快照仍可验证升级）；只有保留窗口内的行复制前一状态以生成行情增量。完整性取舍不变：启动仍校验全部历史，快照不跳过前缀。
- `Engine.apply`用投影JSON再解析一次代替深拷贝来保留前一状态（`market_batch`需要前后两份）。
- 实测（同机，HEAD代码取自`git archive`，1000条限价单）：带快照重启8,303毫秒→约300毫秒；顺序应用全部命令11.2秒→约10.5秒（剩余成本为JSON编码、每命令投影审计与行情差分，属上次审查有意保留的检查）。
- 验证：WSL/Python3.14，`-W error`完整套件64项、2子例通过，修改前后相同；未新增测试。

## 已复现并修复

1. **Python值相等掩盖状态类型漂移。** `False == 0 == 0.0`使候选`execution_seq`改成布尔或浮点、重新计算自校验后仍可能获准提升；投影比对和快照兼容也有相同盲点。现在用已有规范化SHA256校验和比较独立重放的完整状态，区分JSON类型，并保持字典插入顺序无关及旧快照验证升级。投影差异报告`projection_matches=false`。
2. **坏数值投影仍可能继续撮合。** 整值float现金与整数总额相等，旧审计不能阻止它进入后续计算。审计现在检查现金/持股余额、订单/成交数量和序号、累计计数的严格整数类型。`Engine.apply`在写入下一命令前拒绝坏投影，游标不推进；从原始日志重建后能继续同一命令。
3. **行情总量一致不能证明订单演进正确。** 无成交旧单可改属主、已撤单可配套L2数量复活，新单也可借用旧创建序号。现在保持已有订单不可变字段，要求filled不倒退、remaining不增加、FILLED/CANCELED终态不改写，新单seq必须属于当前批次；所有检查在事务提交游标、指纹、公开变化和私有报告之前完成。

变更限于[storage](../src/stock_exchange/storage.py)、[snapshots](../src/stock_exchange/snapshots.py)、[audit](../src/stock_exchange/audit.py)、[market](../src/stock_exchange/market.py)与[8项回归](../tests/test_replay_integrity.py)，复用现有校验和/事务，不增加依赖。回归先复现旧实现，再验证修复；正向保护字典顺序无关。额外无网络SQLite实验验证部分/全部成交、撤余量、DAY过期、当前及旧快照恢复、备机提升、同前缀行情重同步均可继续。

## 关键修复和取舍

1. 移除扫描/排序全部历史订单的候选撮合，按最佳价位FIFO头取单；取消/部分成交同步链接/价位数量。链操作O(1)，价格堆操作O(log P)，稀疏堆重整偶尔O(P log P)。整体仍有全量复制/JSON/审计，不能宣传整体O(1)。
2. 分层contracts/policies/order_book/audit/publication/queries/admission/routes/transport/server_runtime。兼容原matching/market导入，不跨章节运行时依赖。所有外部可变输入在等写锁前冻结。
3. 当前尾部/单条重复与事件后缀用索引；账户/订单/请求只传目标对象。head/seq/投影与审计固定同一SQL读快照，行情轮询不再持HTTP全局锁等待网络。
4. 提升不能只信相同seq/head：候选state_hash自洽且完整状态必须等于定序日志独立重放。发布前后校验epoch，消费者再核验epoch/原始定序前缀。在途响应可能仍代表较旧有效前缀，不等于瞬时失效或自动选举。
5. 行情拒绝倒退快照/epoch、同前缀不同状态、同head不同批次内容、非整数/负量/错订单/错成交序号；核对L2与活动订单、订单filled与成交总量。事务提交游标/投影/公开变更/重复指纹。过期且无指纹的重复返回410重新取快照，不能无条件忽略。
6. 新撮合前核对读投影审计，损坏时保持未应用而非用坏索引成交；重启重放修复有效历史的投影。定序请求去重索引损坏则拒绝启动，不自动再受理。快照发布/重建独立锁、唯一临时文件、fsync/有限Windows替换重试；旧格式先验证再从原日志升级。
7. HTTP32/15秒，网关公开16为内部回调保留容量。RPC2秒/轮询5秒共享截止时间，请求1MiB/响应8MiB，严格JSON/长度/凭据/路径/查询/字段，无环境代理/重定向。绑定后才启动非daemon轮询，退出stop/close/join，关闭异常也排空。socket超时不能强杀SQL/CPU或自定义阻塞适配器。
8. 实验清理复现过Windows WinError32，加入仅针对自身已核验临时目录的有限重试，不删除其他实验文件，也不掩盖持续清理失败。

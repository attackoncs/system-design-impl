# 第29章证券交易系统需求

来源：根目录《System Design Interview.md》第29章。仅模拟股票限价下单/撤单，不连接真实交易场所；原书每日十亿订单、毫秒级往返延迟（重点关注p99）及四个九为未验证目标。

- 整数USD美分价格与整数股数量，静态合成账户/持仓；身份、交易时段和风险检查保留抽象。
- 下单/撤单幂等、全序定序、价格—时间优先、挂单价格成交、部分成交、自成交防护。
- 买方现金及卖方持仓冻结、价差返还、剩余撤单释放，无卖空；现金和逐股票股数守恒。
- 保守的每用户/股票/UTC日受理股数限额，取消仍占额度；模拟UTC工作日时段，DAY单在下一日首条指令时过期。
- 每只股票独立逻辑簿，共享单串行撮合/账户事务；持久指令链、确定性结果及快照/尾部恢复。
- 独立主备进程异步复制重放，候选追平后人工切换，持久epoch控制旧主发布；定序器未复制，无自动选主。
- 独立行情/报告投影，序号化订单簿增量、快照、OHLCV、公开数据脱敏和私有双边成交报告；错过窗口返回410并重同步。
- 独立进程验证公平顺序、撤单竞态、主备/定序器重启、快照重放、资金持仓守恒和行情恢复；报告实测p99及边界。

不包含真实时区/节假日日历、生产KYC/合规认证、银行结算、手续费、FIX、多播、WebSocket或跨主机耐久性。

- 补原书接口别名、按股票/订单/时间的认证成交查询、K线时间窗口和连续双边成交序号。
- 价格级FIFO索引、完整状态复制成本显式；逐账户流量/成交数量/索引审计及漂移后拒绝继续撮合。
- 写锁前冻结、损坏去重索引拒绝重启、完整状态提升校验、发布与摄入期间复查epoch/定序前缀。
- 原子行情游标/指纹/报告，拒绝倒退/错内容/错误数量，旧快照/投影升级；查询并行、有界协议/容量/生命周期。

未实现mmap/SBE/FIX/CPU绑核、多播等时公平、Raft选举/定序器复制、独立出站总线、L3订阅与生产规模/真实清算。

## 2026-11-05 重放与行情更新完整性

- 提升、事件重放与投影比对、当前及旧快照兼容性均比较规范状态校验和；区分数值相等的JSON布尔值、浮点数与整数，不受字典插入顺序影响。
- 新撮合前审计投影金额、数量与序号必须是严格整数；数值相等的浮点漂移也阻止继续应用指令，须通过事件重放重建恢复。
- 已有订单的身份与原始意图不可改，只允许remaining/filled/status/reason变化；成交量不倒退、剩余量不增加、终态订单不可改写，新发布订单须来自本批次序号。
- 冲突更新在行情游标、公开变化、重复指纹及私有报告落盘前拒绝，失败保留原投影；这些检查不提供定序器副本或自动选主。

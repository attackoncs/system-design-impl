`python tools/redis_probe.py --url ... --output benchmarks/redis-local.json`

客户端时间分别偏移-1e8/0/+1e8/+9e8秒，Redis脚本忽略这些客户端时间。
两个真实本机HTTP实例(同进程两个服务线程、独立RedisStorage)共32次请求，
配额9，200恰好9、429恰好23，拒绝头为整数秒，所有状态键均有TTL。
独立桶容量实验两算法均以速率2/10秒、容量5放行5次，第6次拒绝，
重试约5秒；确认为独立突发容量。原始数据：[Redis记录](redis-2026-10-27.json)。
本轮启动独立Redis服务，校验run_id后停止，helper进程退出0。
工具不会清库或关闭用户提供的Redis，只删除自身命名空间的键。

文件策略/FIFO演示：[policy记录](policy-2026-10-27.json)，
接纳[true,true,true,false,false]，规则加载1次、FIFO结果[0,1,2]。
原basic_usage.py全部演示通过；输出去除GBK终端无法编码的状态emoji。

每种算法10000次检查，256主体、预热256次、配额100000/3600秒，全部接纳。
1或8客户端；延时从工作线程开始检查到返回，**不含线程池排队时间**；
吞吐包含本次调度/线程池成本。与测试/图构建分开运行。

## 2026-10-31脚本缓存与恢复复核

Windows / Python3.13.9 / redis-py6.4.0 / 独立WSL Redis8.0.5。
全量基线249项/14.63秒；修改后265项/15.00秒，无跳过。
新增16项覆盖输入边界、规则恢复、稳态命令形态、五算法冷缓存竞争与
缓存丢失恢复，以及两种失败策略下超时不重试。
全量采用`-W error`，仅在pytest参数中过滤既有Starlette TestClient的
可选httpx2兼容警告；禁用无关插件、使用独立临时目录。

[真实Redis原始结果](redis-2026-10-31.json)：五算法各128次请求、4个同步
Python进程，配额25，各恰好放行25，存储错误0。两个真实HTTP实例共享
配额9，共32次请求，200为9次、429为23次；所有探测状态键都有TTL。
独立容量实验仍放行5次、第6次拒绝，稳态速率2/10秒。

在同一个本轮专用Redis上，五算法分别消耗一次配额、清除脚本缓存，再继续
检查；每种仍累计允许2次、拒绝1次，无存储错误，说明重新加载脚本没有
重置数据配额。清除脚本缓存仅针对本轮自行启动的独立测试服务，未操作
用户提供的Redis。结束时核对服务run_id并关闭，辅助进程正常退出。

稳态单元检查观察到一次EVALSHA、无完整Lua文本；真实服务命令统计见
原始结果，未执行EVAL。冷缓存/缓存丢失仍会有额外SCRIPT LOAD及EVALSHA。
这里证明的是共享额度、恢复行为与命令形式，没有新旧Redis吞吐对比，
不作提速比例结论，旧版内存微基准与回归说明仍按上文保留。

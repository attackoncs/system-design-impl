# 第13章：WebSocket 与设备游标审查

审查日期：2026-10-24。范围是 `src/chat_system/transport.py`、
`src/chat_system/client.py` 及对应回归测试。

## 章节要求与执行路径

客户端先通过 HTTP 服务发现获取 `ws://` 或 `wss://` 节点，再使用预先签发的
令牌和设备 ID 登录。WebSocket 同时承载请求响应与实时消息、在线状态事件。
服务器会优先调用本地服务的 `async_*` 存储适配方法，避免在事件循环中等待
SQLite；分布式服务已经提供异步方法，继续直接使用这些方法。

`sync` 返回当前用户收件箱中按消息 ID 升序排列的一页消息，`history` 返回
授权频道的历史，`message` 按消息 ID 查询当前用户可见的单条消息。
`next_cursor` 只指向实际返回页的最后一条消息；UTF-8 字节预算可能使实际页数
小于 `limit`，应继续按照游标读取，不能把“小于 limit”当作历史结束标志。

不同设备各自维护游标。实时事件只是提醒，客户端不会用实时事件推进游标：
网络切换、慢客户端断开以及发送确认丢失后，仍然依靠 `receive()` 补齐有序
收件箱。业务成功处理整页后再调用 `acknowledge(messages)`；只有最近一次
`receive()` 返回的完整有序 ID 列表才能被确认，任意较大 ID、截断页和重排页
都会被拒绝。游标先写入独立临时文件，执行 `flush`、`fsync` 后原子替换目标
文件，写入失败不会推进内存游标，可以重新确认同一页。

## 连接与资源边界

- 客户端接收帧上限为 2,000,000 字节，WebSocket 接收队列上限为 16 帧；
  服务器默认请求帧上限同样为 2,000,000 字节。历史响应另有较小的消息字节
  预算，为 JSON 包装和请求 ID 预留空间。
- 请求超时覆盖发送和等待匹配响应的全过程。不断到达的实时事件不能重置
  该期限。非法 JSON、非法响应结构和不一致的收件箱游标会导致连接关闭。
- 单个客户端串行发出操作，取消请求时会丢弃可能处于登录中或结果不确定的
  连接，后续操作重新发现并登录。
- 服务端事件发送设有有限超时；事件写入失败时主动关闭连接，唤醒同时等待
  请求的任务。处理器结束会取消并等待事件任务，上下文退出会逐个释放拥有
  的会话，单个后端释放失败不会阻止其他会话清理。
- 服务端登录有独立期限；传输中断后保留应用心跳的短暂在线宽限，应用心跳
  过期后关闭会话。正常 `logout` 立即更新在线状态。
- `send` 重试必须保留同一个 `client_message_id`，由持久化存储去重。
  `group` 创建没有幂等键，发送后发生连接故障时客户端会报告“结果不确定”，
  避免自动重试创建第二个群组。应用应查询/核对已有群组后再决定后续操作。

## 验证与保留边界

`tests/test_client_reliability.py` 覆盖持续事件下的总超时、登录取消、群组不确定
结果、畸形响应、完整页确认、游标写入失败、非法分页和配置、服务发现响应校验、
异步存储适配、事件写入失败/超时，以及真实回环 WebSocket 的单条消息授权。
`tests/test_transport.py` 继续覆盖实时收发、历史与同步、成员权限、在线状态、
登录超时和 Unicode 字节分页。最终测试数量与结果以 `chapter13-review.md`
记录的整项目回归为准。

游标文件必须专属于一个用户和设备；当前文件格式不包含用户身份或跨进程写入
锁，也不能和业务处理结果做同一个事务。因此客户端业务处理仍应按消息 ID
去重：处理后、确认前崩溃可能重复读取消息。同步 HTTP 服务发现使用工作线程，
取消协程不能强制中断操作系统 DNS 查询；请求的连接/读写超时仍适用。

示例默认使用回环地址和 `ws://`；跨主机部署需要 `wss://`、可信的服务发现、
外部身份管理及相应的容量测试。这里的边界和测试不代表已经验证五千万日活。

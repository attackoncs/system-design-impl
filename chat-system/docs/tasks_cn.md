## 分布式验证结果

- 配置真实 Redis 后的完整测试套件：**55 项通过**，包括原有的 44 个测试、十个 Redis 集成测试和一个额外的 Unicode 字节边界测试。
- Redis 8.0.5 在现有的 Ubuntu WSL 环境中作为临时的仅回环服务器运行。包二进制文件解压到被忽略的项目运行时目录下；未安装任何系统服务。
- 独立的 Python 节点进程通过真实的 WebSocket 连接交换单聊/群聊消息。杀死其中一个进程演练了节点租约过期、共享在线状态、发现替换、客户端重连和持久化游标恢复。
- 共享 Redis 测试验证了并发重试、对过期会话写入的原子拒绝、容量检查、节点实例围栏、令牌吊销以及加入前历史隐私。
- 通知测试演练了向本地端点进行真实的 HTTP POST 投递、离线过滤、由替代工作进程恢复重试状态，以及死信耗尽。
- 启用 AOF 的真实 Redis 关闭/重启恢复了消息、收件箱、凭据、代理条目、通知任务和持久化去重键。重启后重试原始消息没有创建另一个推送任务。
- Redis 网络故障没有对内存回退写入进行确认。大型 Unicode 同步响应按字节限界，并通过返回的游标继续。
- 源码编译和 Python 3.9 语法解析通过。运行时测试使用 Python 3.13，而非 Python 3.9。
- Compose YAML 解析通过，并检查了其中的五个服务。未执行 Docker 构建/启动，因为该主机上 Docker 不可用；直接以独立进程运行是经过验证的部署路径。
- 未进行高规模负载测试、Redis 自动主库故障转移或跨区域仲裁部署。这些明确不在所提供部署的范围之内。
- 变更保持未提交且未推送。

- 最终测试套件：在配置直连 Redis 和全新真实 Sentinel 实验环境后 58 项通过。

## 工程与并发修复

### 存储边界

SQLite 使用 RLock 保护共享连接，允许 `asyncio.to_thread`；BEGIN IMMEDIATE 同时保护跨实例的检查与写入，覆盖私聊配对、群人数、去重和 inbox 扇出。事务失败回滚完整操作。旧库已有重复私聊时保留全部旧频道与历史，只为后续创建选择一个规范入口，避免破坏性合并。

`MessageStore` 保留同步契约；`async_create_direct`、`async_create_group`、`async_add_member`、`async_sync`、`async_history`、`async_get_message` 为本地网络路径提供异步包装。同步历史 API 按条数限制；网络读取使用可选的流式 UTF-8 字节预算，避免先加载1000条大消息后才截断响应。单条查询只允许原始收件人，新增成员不能查看加入前内容。

### 本地路由与资源所有权

TokenAuthenticator 保存随机令牌摘要并按键查找；请求验证只检查相关用户，定期清理才扫描所有会话。消息路由按成员定位设备，状态广播按目标定位订阅者。实时事件复制字典，消费者不能修改其他设备的内容。

提交和实时入队使用同一顺序锁；磁盘 IO 离开事件循环。`run_blocking` 在重复取消时仍等到底层事务结束才释放锁；取消后的已提交内容由同步恢复，不保证对应实时提示已发出。提交期间撤销令牌不向旧会话返回成功确认，已提交的数据不会被撤销操作回滚。

本地推送共享默认8个并发槽，单次10秒期限包括槽位等待；失败诊断默认保留1000条并维护累计失败数。Notifier 默认只记录本地调用，持久重试应使用 Redis worker。活动实时会话归属一个事件循环；兼容未挂载实时消费者时顺序使用 `asyncio.run` 的同步核心调用方式。

### 分布式与客户端

节点启动、关闭和设备接入增加同步与取消期间任务所有权，避免重复消费者和关闭后的僵尸接入。推送任务续租锁，确认、重试和死信写入都原子校验当前令牌；旧消费者不能覆盖已经接管的尝试，已确认条目不重新调用供应商。HTTP 推送拒绝重定向，取消时等待本次请求结束。

历史授权与状态查询使用有界批处理。客户端总请求期限覆盖发送及其间的实时事件；取消、畸形响应后关闭旧连接。确认只接受完整有序的最后同步页；游标写入失败保留原进度，支持再次确认。详细边界见[传输审查](transport-review.md)。

## 明确边界

- 本地 SQLite 仅单机持久化；Redis 同哈希槽、异步复制/Sentinel/WAIT 不提供跨地域共识或同时故障零丢失保证。
- 历史和 Streams 长期保留，磁盘容量、归档、备份和故障域规划仍需运维方案；进程测试不等于长期容量或生产延迟验证。
- 本地推送没有持久通知重试；Redis 外部投递至少一次，提供方必须按稳定幂等键去重。网络超时无法证明外部没有执行。
- 在线状态在 Redis 模式按轮询间隔传播；联系人可见性、用户注册/资料、TLS、实际移动推送绑定由嵌入应用或部署集成提供。
- 客户端游标文件专属于一用户/设备，不包含身份或跨进程锁，也不能和业务处理结果原子提交；业务处理仍应按消息 ID 幂等。
- 附件、端到端加密、全文搜索、已读回执属于扩展范围，没有将它们记为已实现。

# 第 11 章通知系统核对与改进

依据本地《System Design Interview.md》第 11 章（从 `# 11 Design A Notification System` 至下一章）核对，更新日期：2026-10-24。实际执行链已经补齐下列核心参考实现；真实外部服务与分布式部署能力仍按边界记录，不将组件存在等同于已接通。

## 章节覆盖

| 原书主题 | 当前执行证据 | 状态与边界 |
|---|---|---|
| iOS、Android、SMS、Email | 四个 Channel、Provider 契约和独立 worker | 内置 provider 模拟；APNs/FCM/短信/邮件真实接入未实现 |
| 联系人和多设备 | 平台 token 登记、所有端点快照、逐端点投递 | 旧无平台 token 保留兼容；联系人存储仍在内存 |
| 验证客户端、验证地址 | HTTP bearer 鉴权，JSON/大小限制，基本地址格式校验 | 共享内部 key；TLS、客户授权、厂商签名回调仍待部署集成 |
| 异步队列和并行 worker | 按通道独立堆/SQLite 队列、可配置 worker 池 | 参考实现，不提供复制型消息代理和自动扩容 |
| 通知不丢、持久化日志 | SQLite 接受事务、租约续期和恢复、终态原子确认审计 | 至少一次；磁盘/整机容灾和复制未实现 |
| event ID 去重 | event_id/用户/通道唯一账本与任务同事务提交，完成后保留 | first wins；跨重启/队列实例生效，不能消除 provider 外部副作用重复 |
| 无 event ID 的请求 | 内容 hash TTL、用户级接受锁 | 去重限于单 service 实例及 TTL |
| 模板复用 | 解析模板并快照真正入队正文、参数与元数据 | 模板注册表在内存，真实共享模板数据库/缓存未实现 |
| 用户偏好与退订 | 接受时和每次 provider 调用前检查 | 不能撤回已经开始的外部调用，偏好需启动时重新加载 |
| 限频 | 每用户通道额度及该用户跨通道总额 | global 不是全系统配额；跨进程限额未实现 |
| 重试、退避和异常 | 排队延迟重试、超时、异常隔离、领取失败可中断退避 | 永久失败在日志和 tracker 可见；外部告警平台未接入 |
| 多设备部分失败 | 成功/永久拒绝分别保存，暂时失败继续重试 | 有永久拒绝则最终整体 FAILED；检查点前崩溃可能重发端点 |
| 服务端计划通知 | 带时区 scheduled_at 持久化、就绪任务筛选 | 本地调度，无外部定时任务集群 |
| 积压监控 | depth、in_flight 及 HTTP analytics | 实时本地快照；指标平台和自动扩容未接入 |
| 送达/点击跟踪 | 状态机与 verified-caller /events | 当前进程历史；重启后厂商回调状态重建未实现 |
| 数据库、缓存、水平扩容 | 持久待处理任务与审计 backend 可独立替换 | 用户/偏好/模板数据库缓存、分布式 broker、自动扩容尚未实现 |

## 本轮修复

原链路只用模板结果参与去重，却把未渲染的请求入队；provider 异常会使 worker 退出；重试在 worker 内 sleep，而且队列被新请求填满时可能丢重试。默认日志仅内存且成功尝试未记录，HTTP 示例未启动 worker，也没有持续运行事件循环与鉴权。

现在接受请求时快照真正渲染内容和端点，拒绝不消耗限额；队列领取预留容量，延迟由队列安排。SQLite 将任务、接受审计和事件 ID 账本放在同一事务，租约凭据保护重新领取后的数据；取消、暂时队列错误、provider 异常和混合设备失败都有恢复路径。内存旧凭据也被拒绝，避免确认完成后被错误补偿复活。HTTP 示例接通真实运行的 worker，并要求内部 key。

## 可执行启动

```powershell
# 在 notification-system 目录，先完成 pip install -e ".[dev]"
$env:NOTIFICATION_API_KEY = 'local-demo-key'
python examples/demo_server.py --database notifications.sqlite3 --port 8000
```

默认使用模拟 provider，不发送任何真实第三方通知。共享 key 的请求示例和库启动代码见中英文 README。

## 保留的工程边界

- SQLite 是本地持久 backend，写事务串行，不是 replicated broker；未实测书中每日千万推送容量。
- 联系人、偏好、模板、实时 tracker、无事件 ID 的内容去重和频控窗口在内存。恢复 worker 前要重新加载元数据，跨进程配额需要共享实现。
- 事件账本清理策略独立于审计日志；默认持续保留，不能长期无界写入而不制定策略。
- provider 接受后、本地 ack 前进程崩溃会重发；使用真实渠道时还需稳定的逐端点外部幂等键。
- SENT 表示 provider 接受，不等价于终端收到。审计是尝试和队列事实记录，可能有相同状态的多条事实；FAILED 尝试不代表整条通知最终失败。送达与点击回调的跨重启重建尚未实现。
- 真正厂商适配、TLS、客户授权、签名回调、外部告警、元数据共享缓存、自动扩容及跨主机容灾仍待集成。

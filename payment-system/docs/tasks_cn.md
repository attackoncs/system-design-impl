# Tasks: Payment System

来源：根目录 `System Design Interview.md` 第 27 章，章节起始行 13482。

状态：参考实现完成；48项测试通过，四进程HTTP演示与实际压测已运行。仅使用本机模拟PSP；尚无真实资金渠道、权威库复制/HA或生产规模验证。

## 范围

电商单币种收款、向卖家付款、第三方 PSP 接口及对账；不保存卡号，只使用模拟/沙盒供应商。

## 实施任务

- [x] T1. 编写需求/设计，定义订单/支付/执行记录、钱包、复式账本和金额最小单位。
- [x] T2. 实现 pay-in/pay-out 状态机、请求幂等键、供应商令牌引用及托管收银台接口。
- [x] T3. 实现 PSP 模拟适配器、webhook 校验/去重和乱序状态更新；真实收费/出款不在本任务授权内。
- [x] T4. 实现复式不可变账本，校验借贷平衡并关联业务/供应商交易 ID。
- [x] T5. 实现网络超时后的未知状态、主动查询、指数重试、重试队列和死信，禁止盲目重复扣款。
- [x] T6. 实现内部账本/支付记录/供应商账单异步对账和人工复核队列。
- [x] T7. 实现 outbox 等内部事件一致性机制，明确业务一次生效与网络至少一次投递的区别。
- [x] T8. 验证重复/伪造回调、支付延迟、故障恢复、重复出款抑制、账本不变量及对账差异。
- [x] T9. 提供可运行示例、英/中文 README、设计取舍及实际测试/压测报告，更新根目录状态；未验证的生产规模保持明确。

## 验收门槛

- 正确性、持久化重启、幂等和故障路径有可重复测试。
- 分布式能力须用实际独立进程/网络验证，模拟实现单独标注。
- 外部云服务/供应商使用可替换适配器；未配置凭据时不能宣称真实服务已验证。
- 原书规模和可用性数字是设计目标，不由本机测试直接证明。
- 仅在用户要求后提交；docs 下 requirements.md/tasks.md 延续不提交的约定。

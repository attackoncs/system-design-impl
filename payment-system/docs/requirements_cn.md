# 第27章支付系统需求

来源：根目录《System Design Interview.md》第27章。原书约10 TPS为设计目标，不代表本机验证结果。

- 单币种USD整数美分：商户订单收款、向商户出款、部分退款、模拟托管收银台；不接收卡号/银行账号，不连接真实资金渠道。
- 持久化订单/支付状态、执行记录、钱包、复式不可变账本及供应商交易ID。
- 请求键和订单双重去重；供应商使用稳定操作身份；退款累计包含未决退款；并发可用余额不透支。
- 签名回调、时间窗口、事件去重、旧版本忽略、终态冲突/身份差异人工复核。
- 超时进入未知状态，主动查询，指数退避、租约隔离、死信及保留原身份的人工重试。
- 业务状态、账本、钱包及outbox原子提交；内部消息至少一次投递、消费者幂等。
- 供应商账单、本地操作、账本和钱包异步对账；差异记录而非自动改账。
- 通过独立进程HTTP测试故障恢复，记录实测性能及单权威SQLite、无真实PSP/HA等边界。

本参考实现为每笔商户订单创建一笔支付，支持含1..20笔订单的可信checkout；本地操作ID和执行任务同一事务受理，各笔订单独立授权和结算。跨商户原子外部扣款、拒付、税费、FX和真实银行结算不在范围内。

## 2026-11-05 开源与契约复核

对照原章、GitHub固定源码及CodeGraph调用路径，未发现确认的生产代码缺陷；本轮未修改生产代码或测试。一次完整严格验收 **48项通过，22.021秒**，使用 `-W error`、无跳过。以上2026-10-27结果保留为历史。

任务累计计入预算的通信/处理失败，直到管理员重试才清零；正常PENDING轮询既不增加也不清零，累计五次计数失败进入死信。直接claim辅助方法默认两秒租约，HTTP工作进程使用30秒认领租约，每任务共享20秒I/O预算。租约隔离与供应商/账本幂等是不同保护层。可信多订单checkout只保证本地受理原子性，不是跨商户外部扣款原子性。

详见[源码与章节对照](open-source-review_cn.md)及[当前验证](../benchmarks/REPORT.md)。资金仍全部模拟，真实PSP、银行和生产HA边界不变。

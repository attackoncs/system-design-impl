# 第27章支付系统需求

来源：根目录《System Design Interview.md》第27章。原书约10 TPS为设计目标，不代表本机验证结果。

- 单币种USD整数美分：商户订单收款、向商户出款、部分退款、模拟托管收银台；不接收卡号/银行账号，不连接真实资金渠道。
- 持久化订单/支付状态、执行记录、钱包、复式不可变账本及供应商交易ID。
- 请求键和订单双重去重；供应商使用稳定操作身份；退款累计包含未决退款；并发可用余额不透支。
- 签名回调、时间窗口、事件去重、旧版本忽略、终态冲突/身份差异人工复核。
- 超时进入未知状态，主动查询，指数退避、租约隔离、死信及保留原身份的人工重试。
- 业务状态、账本、钱包及outbox原子提交；内部消息至少一次投递、消费者幂等。
- 供应商账单、本地操作、账本和钱包异步对账；差异记录而非自动改账。
- 通过独立进程HTTP测试故障恢复，记录实测性能及单权威SQLite、无真实PSP/HA等边界。

本参考实现简化为一订单一支付；多订单合并支付、拒付、税费、FX和真实银行结算不在范围内。

## 正确性与故障证据

| 场景 | 已验证结果 |
|---|---|
| 20次并发相同请求 | 一个操作ID；同键不同金额、同订单换键均拒绝 |
| 事务提交前异常 | 操作、冻结、账本和执行任务全部回滚 |
| 账本借贷不平衡/篡改 | 不平衡事务不能入账；已入账表头、明细更新/删除被触发器拒绝 |
| 并发超额出款 | 两笔各6000美分争抢10000美分，仅一笔成功冻结 |
| 退款上限 | 未决退款计入累计，超过原支付拒绝；成功退款扣减可用资产与负债 |
| 签名与身份边界 | 伪造签名401；跨商户读取404；商户调用管理API401；额外卡号字段400 |
| 回调重复/乱序 | 重复事件不重复记账；旧版本忽略；同事件变更内容409；金额/终态冲突进入复核 |
| PSP提交后503 | 供应商已提交且回调/查询不可用时，本地出款UNKNOWN、3000美分仍冻结；5次失败进入死信 |
| API/PSP/worker重启恢复 | 恢复查询后重试原出款；最终7000可用、0冻结，PSP只存在收款与出款两个操作，账本三笔事务 |
| 消费者提交后确认丢失 | 至少3次投递、1个持久事件；worker重启后可继续确认 |
| 出款明确失败 | 冻结全部释放，余额回到10000美分，借贷/资产负债审计匹配 |
| 租约过期与死信重投 | 旧认领令牌不能完成新认领；死信通知重投保留原事件身份 |
| 对账异常 | 篡改PSP账单金额或钱包投影会产生差异/复核，不自动修改账本/余额 |

上述PSP提交后503的HTTP测试在worker离线时，通过独立PSP端点提交原操作模拟丢失响应，再恢复worker查询，确定性控制故障窗口；同时单元测试覆盖供应商重复创建同一请求只返回原身份。

演示实际结果：收款10000、出款3000、退款2000；最终可用5000美分，冻结0；5笔已入账事务；模拟PSP三笔成功操作、消费者三个唯一事件；异步对账零差异。服务与临时数据库退出时清理。

## 实测性能

数据文件：[latest.json](latest.json)。20笔100美分收款，4个并发客户端，单worker；每笔包括受理、等待checkout、自动批准和等待本地成功：

| 指标 | 结果 |
|---|---:|
| 完成全部支付用时 | 4.2104秒 |
| 完成收款吞吐 | 4.7502笔/秒 |
| 全流程p50 | 801.99毫秒 |
| 全流程p95 | 970.59毫秒 |
| 最终可用/冻结余额 | 2000 / 0美分 |
| 模拟PSP唯一成功操作 | 20 |
| 消费者唯一事件 / 投递次数 | 20 / 20 |
| 内部与供应商对账 | 匹配，无差异 |

计时包含自动批准收银台和40毫秒客户端轮询，不包括进程启动、最终outbox排空及对账等待。最终余额、事件数与对账在计时结束后另行断言。这是一次小样本端到端测量，不能据此推断稳定容量、银行卡授权延迟或真实网络表现。

原书约10 TPS仍是设计目标，**该样本没有达到该目标**。当前单worker轮询与串行SQLite事务限制吞吐，未尝试通过省略持久化或金额校验优化数字。无长时间稳定性、跨主机网络、权威库HA、真实PSP、外部银行结算或PCI验证。

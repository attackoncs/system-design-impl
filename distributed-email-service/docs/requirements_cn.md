# Requirements: Distributed Email Service

依据根目录《System Design Interview.md》第 24 章。参考实现覆盖 HTTP 邮箱、发送/接收、已读筛选、主题/发件人/正文搜索、附件与可替换扫描边界。身份认证以静态令牌适配点接入，不实现完整账号体系。

1. 邮箱按用户固定分片，主库元数据与倒排索引持久化；独立只读节点通过 HTTP 异步复制。副本可承担故障期间的陈旧读取，但不得自动接受写入。
2. HTTP 发送采用持久化幂等键与队列；独立工作进程通过真实本机 SMTP 协议传输到已配置的 `local.test` 邮箱。不得查 MX 或向外部地址发送。
3. 接收网关在成功确认前持久化原始消息引用和信封；确认丢失后重传同一投递 ID 不重复入箱。多收件人部分失败可重放，删除墓碑防止邮件复活。
4. 正文、原始 RFC 消息与附件在独立 HTTP 对象服务保存，SHA256 完整性校验；附件下载必须先校验所属用户和消息状态。
5. 附件最多 3 个、每个 2 MiB、完整 RFC 消息最多 8 MiB，正文 65536 字符；元数据数据库不得保存附件二进制。
6. 邮箱/搜索分页至多 50 条；支持已读过滤、主题/发件人/正文精确词项 AND 搜索；标记已读/删除使用版本条件更新防止丢失写入。
7. 扫描接口可替换；未配置真实扫描器时标记 unscanned 并隔离，测试标记规则不得宣称真实反病毒/反垃圾。扫描不可用保留队列重试，隔离附件禁止下载。
8. 验证真实网络收发、重复确认、节点恢复、元数据复制、读状态冲突、搜索删除同步、附件损坏及授权边界，并提供实测报告。

不含公网邮件投递、MX/DNS、IMAP/POP、真实 AV/反垃圾、完整 OAuth 身份、HTML 富文本、安全附件预览、对象复制、自动元数据主从切换或生产十亿用户容量。所有邮件与收件人均为本机合成测试数据。

2026-10-26工程复核验收：固定文件夹统计/查询、本人持久化长轮询和lineage游标、
可选读屏障、按水位失效的有界元数据缓存、严格复制重放、发送/接收租约栅栏及
有界direct HTTP/SMTP生命周期。验证并发、资源关闭及实际网络行为；真实AV、HA与规模仍是缺口。

# 设计：附近好友

## 职责与存储

参考实现选择原书的Redis路线：独立WebSocket进程、同机共享SQLite WAL、真实Redis缓存和
Pub/Sub。Erlang/BEAM是替代方案，附近陌生人是额外功能，不自动纳入好友授权范围。

| 模块 | 职责 |
| --- | --- |
| core.py | 用户、双向好友、共享/历史设置、顺序位置和历史事务 |
| models.py | 领域错误、JSON、ID/位置/分页/时长校验和稳定球面距离 |
| schema.py | 幂等建表、过期/反向好友索引的原地迁移 |
| routing.py | Redis URL校验、不可变的一致性哈希环 |
| backend.py | 有界Redis镜像/修复、提示发布、最终授权快照及客户端生命周期 |
| protocol.py | 有界UTF-8 JSON、重复/非有限数字拒绝、操作字段声明 |
| work.py | 有界同步执行器、取消后等待底层工作退出 |
| server.py | 会话准入、串行发送、订阅、对账及后台清理 |
| cli.py | 服务参数、私有凭据创建和资源关闭 |

每次SQL操作拥有并关闭连接；WAL读事务保持一致，写操作仍串行。TTL/历史保留配置持久化，
重启时不被CLI默认值覆盖，拒绝布尔、非有限、非正数和Redis毫秒TTL无法表示的时长。
已有表不重建；补充current(expires)和friends(b,a)索引，避免过期和反向好友全表扫描。

## 上报顺序、权限与过期

双方互认好友并开启共享才能相互查看。上报含有限经纬度/Unix时间戳及可选device；按用户
维护跨设备严格递增时间戳。时间必须晚于服务器now−TTL，最多超前30秒；now在取得SQLite
写锁后才采样，防止排队时已过期的数据被重新延长寿命。接收时间决定TTL，客户端时钟
偏差不延长在线状态。版本、当前位置和已授权历史同事务提交，历史写失败全部回滚。

关闭共享会删除当前位置并推进版本；重新开启需要新时间戳/报告。断线本身不会立刻隐藏，
保持到TTL。历史默认关闭，开启只记录未来报告；关闭删除已保留历史。历史接口只读本人，
即使兼容消息带target也不改变权限，默认24小时保留。

reports在一个读事务中、用一次now采样筛选本人和好友。过期位置立刻逻辑隐藏；后台按
min(30秒, TTL)尝试物理清理，失败重试，上报热路径不再全局sweep。负载或停机可推迟删除。
SQL的单条当前位置是对原书瞬时Redis缓存的恢复扩展，不是未经授权保存多条历史；磁盘、
WAL和备份仍需生产保护，关闭历史不等于清除所有备份副本。

## Redis是有界镜像

报告先提交SQL，再尽力写Redis并发布提示；没有事务outbox或频道回放。Lua禁止较低版本
覆盖较高版本，TTL只用服务器接收时间的剩余期。Pub/Sub只传用户ID提示，不传坐标。

snapshot先读授权SQL报告，再MGET/可选修复缓存，最后重新读取SQL。最终一致读决定返回的
每个位置，复核双方TTL、位置、好友和共享状态；Redis不决定响应，缓存命中也不会避免SQL
读取。这是清晰的本地隐私/顺序权威与查询成本之间的取舍，不是原书Redis-only快速路径。
生产若以Redis为权威，需另外设计撤权epoch/fence和故障切换规则。

一次MGET失败即停止修复，不放大为每好友一个超时；pipeline每批最多128条，默认1秒预算
在批间检查，不能中断已执行的网络调用。同步客户端池上限16，连接/读写超时0.5秒，无
配置自动重试。Redis URL只允许db查询参数，不能覆盖资源或超时参数。

broker客户端最多32项LRU，发布者持有使用租约，只淘汰空闲项；全部在用时可丢弃本次提示。
关闭/发布I/O在生命周期锁外执行。Backend关闭拒绝新操作，等待已接受工作再关连接池。
每会话的异步订阅客户端另外为每broker组拥有一个连接，不共享同步池。

## 路由与投递

Ring含1..32个broker，每个ID有64个虚拟点，节点和token为自有不可变数据。同一ID替换
地址不改变token位置；管理员用expected_epoch CAS安装已校验副本。配置保存在同机SQL，
会话轮询，不等于etcd/ZooKeeper共识发现。

频道按发布者用户ID路由；会话订阅自己和全部好友，包括离线好友。配置或好友变化保留
未变订阅，启动替代任务并回收受影响任务；重连置dirty。切换不承诺无缝无损，默认每秒
完整对账修复漏提示、TTL和权限变化。

初始快照最多20位附近好友，含位置、距离和时间戳；新客户端没有有效自身位置时需发送
首条location。显式snapshot支持radius/offset/limit，但分页不覆盖实时增量基线，避免吞掉
其他页面的更新。半径变化也继续按旧基线发送leave/enter/update，客户端按好友ID归并。
增量按每帧最多100项发送，leave只有ID。分页是实时offset，移动会导致
页漂移，应按ID去重。距离采用稳定球面great-circle atan2，不是道路距离。

最终SQL读是本次响应授权时点；此后撤权仍可能与已准备或在途帧竞争，不能收回已投递坐标。
周期恢复提供最终修复，不代表无损频道或对已发送字节的即时撤销。

## 协议、容量与关闭

升级请求只能有一个Authorization头，认证在初始应用数据之前执行。仅接收16KiB以内
UTF-8 JSON文本，拒绝重复键、非有限数字、二进制和未知操作字段；request_id可选且为
1..64字符。应用输出帧上限256KiB，入站队列高水位16、write_limit为32768字节。每会话
发送串行，单个响应或整批多帧增量共用默认3秒绝对期限；不会随帧数放大等待，慢消费者关闭。

默认256上限统计已升级应用会话（含认证），不是TCP/握手硬配额；握手期限5秒、backlog128，
入口仍需部署限流。WorkPool默认16worker，同时至多提交16个同步SQL/Redis调用，会话等待任务
受已准入数量约束，另有受控维护任务。取消等待者后仍持有容量并排空已接受工作，再传播取消，
防止后台孤儿写入。

CLI增加--max-connections、--workers、--send-timeout。关闭停止准入，关闭套接字、回收
订阅，取消/排空清理任务并等待同步调用退出，最后关Backend池。绑定失败不会启动清理。
系统DNS、SQLite和部分已执行网络I/O不能被强制取消，故不能承诺绝对关闭时限。

provision独占创建凭据文件，先写入并flush/fsync再创建SQL用户；失败仅删除身份仍匹配的
自有新文件，不覆盖已有文件。支持的平台用0600模式，Windows文件夹ACL仍由部署保护。

## 验证与部署边界

[章节核对](chapter18-review.md)和[验证报告](../benchmarks/results.md)集中记录实际运行。
实验为每个Redis生成随机密码，清理前核对run ID，不会把端口竞争中的其他服务当作自有实例。
只停止自有进程，诊断文件保留在忽略的.runtime/lab-*。

每会话仍完整读取好友集合，SQLite单写者和双SQL读取都有成本。尚未部署Cassandra、用户/历史
物理分片、Redis主备、云地域、共识发现、TLS、生产身份/关系服务、负载均衡摘流、备份恢复，
也未证明书中千万连接、334K上报/秒或约14M转发/秒。Erlang和陌生人路线仍为替代/扩展。

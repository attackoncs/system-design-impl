# 设计：附近好友

## 状态与权限
两个独立的 WebSocket 服务器共享 SQLite WAL 引用元数据与 Redis。
SQLite 事务存储哈希后的凭据、用户/共享/历史同意记录、双方互认的无向边、
请求、每个用户单调递增的版本号、当前报告以及已授权历史。每个用户记录一条
已接受的时间戳序列，防止延迟到达的第二台设备把位置向后回退。

持久化的当前行是对书中瞬时缓存的本地恢复扩展；长期无活动后行会被清除。
在用户未授权之前，它不构成位置历史。

每条被接受的报告先提交权威状态，再以尽力而为的方式更新 Redis 缓存并发布到
Pub/Sub。Redis Lua 只允许缓存版本号单调递增地替换；TTL 采用剩余的服务器端
接收存活期。快照以批量方式拉取缓存，对照权威元数据校验版本号；若缓存缺失
或过期，则回退到当前状态。因此缓存故障可能丢失提示，但不会让旧坐标生效。
隐私等级通过单调递增的版本号来体现；关闭共享会清除当前状态并递增版本号，
重新开启则必须依赖新的报告。历史默认禁用；开启后仅影响未来的报告。关闭历史
会删除已保留的历史记录；可配置的保留策略通过定期扫描执行。

## 投递
Bearer 认证放在 WebSocket 升级请求头中；未通过认证的对端在应用数据之前即被
关闭。每个连接的队列与帧大小由 WebSocket 库设定上界。会话订阅自己以及所有
好友（包括不在线好友）的频道。Broker 连接错误会触发重试。频道使用发布者的
用户 ID，加上一个每个 broker 64 虚拟节点的 SHA-256 一致性哈希环；token 放置
依据的是 broker ID，而不是端点地址。管理员通过带预期 epoch 的 CAS 替换持久化
的哈希环。这个本地共享配置替代了 etcd/ZooKeeper，但不声称具备共识发现能力。

当哈希环或好友关系变动时，会话取消旧订阅、挂载新订阅，并从当前状态重新对账。
Pub/Sub 事件只包含用户与版本号提示，绝不包含坐标。接收方自行计算完整的授权
附近好友集合。一个独立的周期性对账（默认 1 秒）修复丢失事件、TTL 过期以及
权限变更。每个连接上的发送是串行化的。初始快照分页大小为 20；进入/更新/离开
的增量覆盖完整集合；离开只包含 ID。显式的快照分页是实时 offset 视图，而不是
不可变游标，所以好友位置变化可能让页码漂移。客户端应对 ID 做去重，或再次
请求第零页。快照与载荷生成属于同一条 SQL 读事务；撤销可能与已经发出的帧竞争，
但会在下一次对账中生效。不声称可以撤回已投递的数据。

## 限制与运行
默认半径 5 英里，最大 100 公里；默认过期 600 秒。客户端时间戳决定顺序，但
服务器接收时间决定 TTL，因此客户端未来时钟偏移无法延长存活期。共享的 SQLite
串行化写操作；Redis 缓存/发布跟随 SQL 提交，没有事务性 outbox。发布失败由
周期性快照读取修复；重新发现时的缓存预热是按需驱动的。SQLite 不适合书中给定
的写量级。自查询历史 API 与显式遗忘实现了数据最小化；活跃服务期间的定期清理
是机会性的。生产环境需要 TLS、外部身份/关系服务、分布式 SQL、区域本地缓存、
发现机制高可用、备份、可观测性、负载均衡/摘流、时钟监控，以及更大持续负载
下的验证。

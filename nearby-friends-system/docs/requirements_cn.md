# 需求：附近好友（第18章）

依据仓库《System Design Interview.md》第18章（6726–7293行）。核对日期2026-10-25。
详见[章节记录](chapter18-review.md)。

## 功能约定

- 返回已授权附近好友的位置、球面直线距离及最后更新Unix时间戳。默认8046.72米（5英里），
  可配置到100km，不自动扩圈；初始20项，支持实时offset分页。
- 使用真实WebSocket传输location、snapshot及enter/update/leave。连接初始化读取当前状态，
  新用户需上报位置才能建立可见状态。30秒为客户端建议上报间隔，非强制服务端定时器；
  默认600秒无活动则隐藏。
- 双方互认好友并开启共享；可选Redis操作后再次SQL读复核授权。此后撤权可能与在途帧竞争。
  关闭共享删除当前位置，重新开启需要新报告。
- 经纬度/时间有限且范围有效，时间晚于TTL窗口且最多超前30秒；跨设备按用户严格递增。
  时间窗口校验与TTL起算在拿到SQL写锁后进行。
- Redis真实TTL镜像和按发布者用户ID的Pub/Sub频道，一致性哈希路由；提示允许丢失，
  重连、配置/好友变更和周期对账恢复当前集合，不承诺事件回放。
- 历史单独授权、默认关闭、本人可读，默认保留24小时，关闭删除。过期数据逻辑隐藏并后台
  定期清理，不逐次上报执行全局sweep。
- 管理员以expected_epoch CAS更新Ring；保存已校验的自有不可变节点副本，Redis URL不得
  覆盖超时/连接池资源参数。

## 资源和生命周期

应用会话、已提交同步工作、Redis池、broker客户端保留、修复批次、输入/输出帧与发送均有界。
默认256应用会话、16同步调用、每同步池16连接、最多32个broker客户端、每修复批128条、
批间检查1秒预算。取消不能丢失已接受I/O的所有权，底层工作退出才释放容量；先关闭会话、
订阅/维护并排空工作，再关连接池。应用准入不等于TCP硬配额，DNS或SQLite不能靠这些预算
强制中断。凭据独占私有文件先写入并fsync，再创建SQL用户；应用日志不记录坐标/token。

## 验收与边界

真实独立WebSocket/Redis进程验证入圈/出圈、TTL、顺序、撤权、共享关闭、重连、分页、
漏提示和Ring变更；单元注入故障明确标注。实验Redis使用独立随机密码，关停前核对run ID，
只停止自有进程，诊断文件保留在忽略的独占运行目录。

同机SQLite用于用户/好友、单条当前位置恢复和已授权历史；Redis是有界镜像，不消除SQL
读取。这与原书Redis权威快速路径存在成本差距，也不提供跨主机SQL HA或位置缓存物理分片。
Cassandra、用户/历史分片、Redis主备、共识发现、云地域、TLS、生产身份、备份恢复及千万
连接/334K上报每秒尚待部署或容量验证。Erlang为替代方案，附近陌生人为额外功能，不允许
因此泄露好友位置。实际结果见[验证报告](../benchmarks/results.md)，不把估算视为测试结果。

需求/任务文件保留既有本地约定。

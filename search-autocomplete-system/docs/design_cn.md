# 设计：搜索自动补全系统

## 章节映射

本章将"采集/构建"与"在线服务"两部分解耦。本模块通过持久化 SQLite 事件日志、批量处理 Worker、不可变 Trie 快照、查询缓存、分片映射以及实际的 HTTP 查询副本/协调器来实现这一分离。

```text
已完成搜索 → 仅追加事件 → 时间窗口聚合 → 批量 Worker
                                                       |
                                    带版本的原子快照 + 分片映射
                                                       |
                                      分片副本：Trie + Top-5 节点缓存
                                                       |
客户端 → HTTP 协调器 → 相关分片副本 → 全局排名前 5 条
               |                        |
       当前已发布版本            持久化屏蔽规则 + 修订号
```

## 数据与一致性

已完成搜索事件携带调用方提供的事件 ID、归一化查询串以及 UTC 纪元时间戳。SQLite 事务会拒绝冲突的 ID 重复使用，并且确切的重试仅计数一次。建议查询本身不采集分析数据，调用方需另行记录已完成的搜索。批量聚合采用 `[start, end)` 半开区间，且并列排序是确定性的。

快照生成包含频次记录、按字典序平衡的分片范围以及构建窗口元数据。发布操作在单个事务中提交所有分片数据与当前激活版本。已有读者继续持有上一代不可变 Trie，直到新一代加载完成。无效构建不会切换活动指针。代（Generation）ID 单调递增；旧代在途请求结束前仍保持可用。

事件日志始终为仅追加模式。过滤规则是带单调修订号的持久化记录。物理排除发生在后续快照中；历史日志仍可用于审计和重建。查询时规则会立即覆盖缓存结果。HTTP 查询必须携带协调器的版本号和规则修订号。无法服务该版本/修订组合的副本返回不可用；查询永远不会静默合并不同代的结果。

## Trie 与请求缓存

每条字符边构成一个前缀；终止节点携带查询串与频次。每个节点缓存其子孙中的最佳五条。常规查找代价为 `O(前缀长度 + k)`，其中前缀长度上限为 50，`k=5`。用内存换取对子树的遍历成本。对缓存候选项的过滤可能需要遍历受影响的子树以重新填充 Top-5；有界 LRU 响应缓存可以平摊该路径成本。后续快照会物理上排除被屏蔽词，恢复正常查找路径。带过滤回退的最坏情况是子树大小的线性函数，并已在文档中明确说明。

LRU 条目包含版本号、规则修订号和前缀。清理/驱逐缓存不会影响持久化数据。Trie 由序列化后的频次记录重建，而非不可信的 pickle 文件。所有 HTTP 输入均有大小上限。

## 分片与副本

按字典序对查询排序，再分成查询条数大致相等的区间。分片映射存储包含的下界和不包含的上界。一个前缀区间可能跨多个分片；协调器仅向重叠分片扇出请求，并合并它们的 Top-5 列表。当排名和过滤规则一致时，从每个分片返回 Top-5 即可覆盖全局 Top-5。

分片查询节点暴露有界 HTTP GET 操作。每个分片可有多个端点。协调器以有限超时重试副本，校验版本号、过滤规则修订号和分片标识；若所需任一分片无有效副本，则返回不可用。该设计保证在部分结果可用的前提下，完整排名始终正确。HTTP 示例在回环地址上运行多个独立 OS 进程。

## 目录布局与运行限制

`src/search_autocomplete/`：Trie、存储、服务、HTTP 传输层与 CLI。
`examples/`：本地批量/查询及多进程网络演示。
`tests/`：确定性正确性测试与真实 HTTP 故障切换测试。
`tools/benchmark.py`：可配置的本地延迟测量工具。

本实现基于 Python 标准库，目标为 Python 3.9+。SQLite 由本地进程共享，它并非分布式高可用存储，且不应通过任意网络文件系统共享。生产部署应替换快照/日志/元数据存储、将副本分布到不同故障域，并增加带认证和 TLS 的管理接口。每周调度由运维手动触发批量 CLI；实时趋势、Unicode 与特定国家排名属于明确的后续扩展点。

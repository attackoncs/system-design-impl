# 第 14 章 Trie 查询与快照审查

审查日期：2026-10-24。

《System Design Interview.md》第 14 章在 Trie 优化部分要求限制前缀长度，并在每个节点缓存前五名。本实现保留最多 50 个字符的英文前缀、按频次降序及查询字典序排序的五条缓存。普通查询只走前缀路径并返回该节点缓存，时间为 `O(p + 5)`，其中 `p <= 50`。

## 本次修复

- 构建阶段使用私有可变节点，完成后生成冻结节点、只读子节点映射和元组缓存；根节点同样不可重新赋值。并发读者可以安全共享发布后的同一份 Trie。
- 插入时只为不存在的子节点分配对象，避免 `dict.setdefault(char, Node())` 对已经存在的前缀仍然创建临时对象。
- 即时屏蔽导致缓存不足五条时，使用优先队列按子树排名上界寻找补位候选；剩余子树无法超过当前第五名时停止。每个节点的终止查询单独检查，因此低于缓存五条的终止查询也能正确补回。
- 快照入口拒绝未规范化、重复、超长查询，以及布尔、非整数和非正数频次，避免把无效索引发布给查询服务。

## 复杂度边界

即时屏蔽不能保证固定时间：大量高排名候选均被屏蔽时，仍可能访问整个匹配子树。此次改动消除了“任何一条缓存被屏蔽就无条件遍历全部后代”的行为；后续离线构建仍应物理移除被屏蔽条目。没有据此宣称达到书中线上 100 毫秒或特定吞吐量目标。

一个包含 17,576 条等频查询的回归场景中，屏蔽第一条后，查询补齐正确的五条结果，仅进行了 108 次屏蔽集合成员检查。该场景说明低排名分支受到剪枝；这不是通用延迟或最坏情况保证。

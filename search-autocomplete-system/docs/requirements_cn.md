# 需求：搜索自动补全系统

来源：根目录 `System Design Interview.md`，第 14 章，Design A Search Autocomplete System。

## 功能需求

- R1：仅匹配查询串的起始位置，按历史频次降序返回最多五条建议，频次相同时按字典序排序。
- R2：支持小写英文字母和空格（本章包含短语）。对大小写和空白进行归一化；查询串和前缀上限 50 字符。空前缀不返回建议。拒绝其他字符；不做拼写纠错。
- R3：向持久化存储追加带时间戳和稳定事件 ID 的已完成搜索事件。重试同一事件不得重复计数；冲突的重复使用会被拒绝。
- R4：对显式 UTC 时间窗口做聚合，离线构建不可变、带版本的快照。每周窗口为默认参考用例；建议请求不得更新搜索频次。
- R5：原子化发布快照。读者看到的是完整的某一代。构建或发布失败时，上一代仍保持可用。服务重启时加载最近一次已发布的快照。
- R6：在 Trie 节点缓存 Top-5，并提供按代和过滤修订号索引的有界请求缓存。缓存驱逐或未命中时必须保持正确性。
- R7：在查询时立即屏蔽/解除屏蔽特定建议（包括缓存响应）。被屏蔽的查询在下一次快照构建时物理排除。屏蔽规则由运维提供，而非自动内容分类器。
- R8：将按字典序排序的查询划分成平衡的分片，并维护带版本的分片映射。短前缀跨越多个分片时必须合并出全局 Top-5。
- R9：提供真实的 HTTP 查询节点与一个协调器，协调器联络分片副本、在副本不可用时故障切换，并拒绝不同快照版本混用的请求。缺失的分片返回不可用，而非返回一个排名错误的部分响应。
- R10：提供可运行的本地/网络示例、中英文 README、测试用例以及可测量延迟的工具。部署和规模限制必须显式说明。

## 验证与边界

- 章节目标：响应低于 100 ms，平均约 24,000 / 峰值 48,000 QPS，日活千万。本地测量结果不能作为达到这些容量的证明。
- 测试必须覆盖排名、短语、并列、非法输入、事件去重、时间窗口、快照原子性与重启、缓存驱逐、过滤、多分片合并、真实 HTTP 副本故障以及版本不匹配场景。
- 初始存储为主机上的 SQLite；查询副本加载不可变快照。多主机对象存储、分布式日志采集、共识元数据、自动基础设施编排和实时趋势属于后续扩展，而非已声明特性。
- 除非用户改变现有策略，否则不要提交 requirements.md / tasks.md。

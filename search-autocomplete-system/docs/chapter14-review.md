# 第 14 章：搜索自动补全核对

对照根目录《System Design Interview.md》第 14 章（4289–4763 行），重点核对
原书的最终离线构建方案。小数据量 SQL 查询和逐节点更新属于中间方案/可选替代，
本项目采用批量替换整代 Trie。

| 原书内容 | 当前实现及范围 |
| --- | --- |
| 前缀匹配、历史频次 Top 5、最长前缀 | 英文字母和短语；确定性频次/字典序排名；50 字符上限 |
| 每个 Trie 节点缓存 Top 5 | 不可变节点、子映射和整树；正常查询只沿前缀查找 |
| 日志、按周聚合、离线 Worker | 事务事件日志、持久窗口聚合、可复用聚合 ID、周期 SnapshotWorker |
| 1/N 数据采样 | Collector 根据事件 ID 稳定采样，跨进程和重试一致 |
| 整代更新、数据库回源、Trie 缓存 | 单调构建票据、原子发布、两代快照/256 棵 Trie 和有限结果 LRU |
| 即时移除及异步源清理 | 实时过滤修订栅栏；独立 purge-blocked 或 Worker 可选清理 |
| 不均匀首字母与更细分片 | 按历史不同查询数均分字典区间，支持跨多个字符的边界和跨片前缀 |
| HTTP 查询及副本恢复 | 真实本地进程、备用副本、完整排名合并、版本/修订/归属校验 |
| 一小时浏览器缓存 | 可选优化未启用；no-store 保证浏览器不绕过即时过滤 |
| 高可用、千万日活及 100ms 目标 | 提供本地机制和有限测量；未验证多主机存储 HA 或互联网规模容量 |
| 多语言、地域/CDN、实时热点 | 原书后续讨论，未作为当前核心范围实现 |

## 本轮修复

- 跨实例读后写竞争改为 SQLite 写事务；同时初始化数据库的 WAL BUSY 有有限重试。
- WAL 输入快照与 Trie/JSON 构造分离，避免离线计算持有在线存储写锁；旧构建不能
  覆盖较新发布，屏蔽修订变化时拒绝发布。失败构建可能留下版本号间隙。
- 本地冷加载通过固定数量的分段锁合并，昂贵构造移出全局 LRU 锁；缓存命中也在
  返回前复核过滤修订。首次构建前的合法查询返回不可用，而非参数错误。
- 屏蔽集合按持久修订缓存，跨实例更改会刷新；最终栅栏只查询一条元数据，避免热
  查询重复扫描全部屏蔽词。
- 过滤补位使用排名上界和优先队列，准确保留 Top 5。17,576 条查询的单词屏蔽
  回归只需 108 次屏蔽集合探测；大量屏蔽仍可能访问整个匹配子树并产生堆开销。
- 协调器所有未结束工作共用容量槽位，超时不会提前归还运行中任务的容量；总预算
  覆盖排队和副本切换，慢响应头/正文可中断，关闭时等待自有任务和 HTTP 处理线程。
- 采集、调度与 CLI 分层，提供持久聚合检查、采样和源清理入口；清理保留查询摘要
  去重凭据，避免事件重试复活删除内容。

## 运行与一致性边界

默认 Worker 按“本次构建时间之前七天”统计，立即执行后再等待七天，进程重启会
重新执行；自然周需要显式 UTC 起止时间。停止等待可中断，当前原子构建允许完成。
源清理显式启用，删除全部旧聚合工件使其 ID 不再可读；历史服务快照保持不可变，
解除屏蔽可能让保留快照中的词再次可见，快照保留必须另行管理。

缓存/任务上限按条目计数，不代表 RSS 字节上限。事件、快照、聚合及去重凭据没有
自动保留回收。SQLite 为单主机共享持久层；元数据锁等待、SQLite 操作及系统 DNS
不能被请求期限强制取消，关闭会等待自有执行结束。未宣称 48,000 QPS 或千万日活。

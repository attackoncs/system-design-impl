# 设计：视频流媒体系统

## 数据流

```text
客户端 -> 已认证 API -> 可过期分片授权 -> 原始对象存储
                               |                            |
                          视频元数据              持久化 DAG 任务
                                                            |
                                  检查 -> 码率版本 + 缩略图 -> 发布
                                                            |
                                                  完成出站队列
                                                            |
                                    处理器 -> READY 元数据 + 编码对象映射
                                                            |
                          播放授权 -> 有边界的边缘缓存 -> HLS/分片/密钥
```

原始章节中的上传、元数据、转码和完成路径相互分离。SQLite 存储凭据、授权签名密钥、上传分片、视频状态、任务、租约和完成出站队列。基于内容寻址的文件在元数据引用它们之前通过原子重命名和 fsync 写入。API/工作进程共享本地存储；真实多主机部署需要复制化的数据库和对象存储适配器。

## 上传与授权

所有者凭据通过带外方式配置。上传请求声明总字节数和固定分片大小；HMAC 授权绑定每个分片的视频、索引、预期长度和过期时间。完整分片可幂等地重试；冲突字节会失败。完成操作将分片流转为源对象，并在原子调度 DAG 之前校验总分片的 SHA256。中断的完成操作可能留下未被引用的对象，但不会暴露已就绪的视频。所有者无法完成其他所有者的上传。

## 调度与发布

每次申领在 SQLite 写事务中获取 UUID 租约令牌、有限过期时间和尝试次数。依赖完成状态控制申领；不同工作进程可以并发编码码率版本。重试使用持久化的到期时间。过期的工作进程仅产生特定尝试的输出，不能完成其他所有者的租约。不可恢复的检查失败会取消依赖。HTTP 调用者不提供任意命令：FFmpeg 命令模板和码率版本配置文件是固定的。

发布仅在所有码率版本/缩略图任务完成且其对象存在后创建主播放列表。持久化完成行携带完整的资源映射；单独的处理器在事务中将元数据改为 READY。出站队列创建与处理之间的故障可以在重启后恢复。下架操作增加状态并立即阻止授权；运行中的工作进程不得恢复已删除的视频。

## 媒体与播放

FFmpeg 生成 H.264/AAC 的 HLS（HTTP Live Streaming），采用对齐的两秒 GOP/分片、点播播放列表、固定码率版本尺寸（通过填充保持宽高比）以及 PNG 缩略图。AES-128 使用每视频随机密钥加密媒体分片。HLS 播放列表引用已授权的密钥路由；服务器将播放授权传播到嵌套的播放列表、分片和密钥 URL 中。密钥传递为 private/no-store。这是访问控制和加密传输资源，而非 FairPlay/Widevine DRM（数字版权管理）。

边缘引用为小对象使用有边界的 LRU（最近最少使用）。缓存读取前检查授权和当前视频状态。大资源以有边界的分块方式流式传输；单字节范围请求按需返回 206/416。循环回环演示的远程部署必须在前端终止 HTTPS。签名/加密密钥位于本地可信持久化存储；生产环境的密钥管理/KMS（密钥管理服务）是适配器/部署任务。

## 操作边界与验证

租约必须超过每个任务的硬性媒体超时时间；崩溃的进程在过期后恢复。资源分配为有边界的工作进程/编解码器并发，而非 GPU 集群管理器。上传分片是字节块；FFmpeg 在服务端处理 GOP 对齐输出，而不是假装任意上传块可独立播放。对象/元数据写入是有序的而非分布式事务；未被引用的文件可以保守清理。原始源文件保留用于重新编码。

测试区分确定性的假媒体故障场景与实际 FFmpeg/HLS 播放。容量报告描述夹具持续时间、码率版本、延迟和进程布局。本书的五百万用户/CDN 成本示例是来源假设，不是当前供应商定价或此实现的容量声明。

媒体配置遵循 [FFmpeg HLS 官方文档](https://ffmpeg.org/ffmpeg-formats.html#hls-2)。

## 跨主机存储与元数据高可用扩展

使用私有 S3 兼容存储桶作为权威对象存储。每个主机有自己的暂存/工作目录。对象引用保留本地适配器的内容寻址键；传输验证 SHA-256 并原子替换临时下载。即使工作进程已有缓存副本，发布前仍检查远端是否存在。垃圾回收仅列出此部署的前缀，保留元数据引用并应用宽限期。存储桶版本控制/备份由运维负责。

PostgreSQL 是可选的元数据后端。最初，数据库范围的事务咨询锁串行化变更，在主机间保留现有状态机不变量；这是刻意的正确性优先吞吐量限制。读取为自动提交。多主机 libpq DSN 使用 target_session_attrs=read-write 来发现主节点；失败时丢弃连接。下次操作重连，同时报告失败的事务而非重放。中断的 COMMIT 是歧义的，必须通过持久化状态和幂等操作来协调。

部署使用三个 Patroni/PostgreSQL 实例、三个 etcd 成员和严格的同步复制。仲裁丢失或缺少同步副本会以写入可用性换取持久性。自动提升需要健康的仲裁和合格的备用节点。Compose 实验使用一台机器；真实多主机部署需要分发故障域。SQLite 数据迁移为离线操作，需要空的 PostgreSQL 目标，并保留签名凭据和租约。

# 需求：视频流媒体系统

来源：根目录 `System Design Interview.md`，第 15 章，设计 YouTube。

- R1：上传并观看小/中型视频，可配置最大 1 GB。元数据和视频字节走独立路径。不含推荐/评论/直播。
- R2：颁发已认证、可过期、分片特定的上传授权。接受可恢复分片，校验长度/校验和，拒绝冲突重试或其他所有者。
- R3：持久化上传状态、源对象、任务依赖、租约和重试。完成操作需要每个分片和声明的总大小；可选的完整 SHA256 校验组装后的源。在所有资源存在之前，元数据不得变为 ready。
- R4：执行离线 DAG（有向无环图）：检查 -> 并行码率版本/缩略图 -> 发布。工作进程原子地申领任务；过期的租约所有者不能完成已回收的任务。可恢复的故障以有界退避重试，畸形媒体立即失败，耗尽的任务进入持久化失败状态并取消依赖工作。
- R5：提供实际 FFmpeg 适配器、可播放的多分辨率 HLS（HTTP Live Streaming）、对齐的关键帧、缩略图输出，以及带授权密钥获取的 AES-128 加密分片。仅测试用的媒体适配器绝不能描述为实际转码。
- R6：在完成出站队列中持久化发布；处理器在所有输出存储后原子更新 ready 元数据。崩溃重放不能重复发布或丢失完成。
- R7：提供有边界的 HTTP 元数据/上传/播放操作、HLS 清单/分片、字节范围和可过期播放授权。下架操作必须覆盖缓存投递。
- R8：使用可插拔的对象/媒体接口和有边界的读取缓存作为本地 CDN 参考。清理操作删除废弃分片/尝试文件但不删除活跃资源。
- R9：运行实际 FFmpeg 和网络/进程测试，覆盖上传中断、工作进程租约恢复、重试、损坏媒体、加密播放和完成恢复。
- R10：发布示例、实测媒体处理结果和英/中文 README。SQLite/本地文件是参考持久化，而非分片/复制化云存储。

- R11：支持 API 和工作进程共享的 S3 兼容私有存储桶，具备独立的本地目录。下载时校验 SHA-256，绝不将本地缓存存在视为远端持久性，并在 GC（垃圾回收）期间保留被引用的对象。
- R12：通过多主机 DSN 支持 PostgreSQL 主节点发现，跨连接的事务性申领和租约 fencing（隔离），以及主节点丢失后的重连。不自动重放不确定的写入/提交。临时数据库故障以 503 暴露；工作进程恢复轮询而不静默丢失已申领的工作。
- R13：提供可复现的同步 Patroni/PostgreSQL 高可用部署，含仲裁协调和对象存储；将实际故障转移测试与配置验证分开记录。显式暴露 SQLite 元数据迁移。

云 CDN 部署、多区域上传中心、DRM（数字版权管理）集成、自适应播放器 UI、水印、GPU 资源调度和内容审核分类器仍为扩展接口/显式后续任务。

# 设计：文件同步系统

## 组件与一致性

认证 HTTP API、块存储、元数据状态机和设备客户端是相互独立的模块。SQLite WAL
保存身份标识、工作区 ACL、文件、不可变修订版本、可恢复会话、块/引用计数以及
持久化的用户事件。BEGIN IMMEDIATE 在参考实现的多个服务进程之间串行化状态
变更。没有任何元数据读缓存会掩盖写入或 ACL 变更。长轮询基于持久化事件日志和
周期性的数据库读取，因此即使丢失唤醒也不会丢失变更。

## 上传与修订版本

客户端对固定大小的块计算哈希，并按顺序声明其摘要/大小清单。会话 ID 和调用方
请求 ID 标识可重试的工作。同一工作区内的块可以复用，而互不相关的工作区无法
相互探测对方的哈希。块字节先经过校验、压缩和加密，然后才提交其元数据。发布
操作在单个元数据事务中校验所有块、拼装后的文件哈希和配额；修订版本、head、
引用和通知一起提交。未完成的上传绝不会以可下载文件的形式出现。

期望的基础修订版本（expected base revision）为编辑设置围栏。首个匹配的发布
获胜。过期的写入者会收到一个独立的冲突文件，其唯一路径由服务端生成；其会话
会记录该结果，因此重试不会创建多个副本。过期的删除请求会被拒绝。修订版本和
墓碑（tombstone）在显式执行保留清理之前一直可用。配额按保留修订版本（包括
冲突副本）加上进行中上传预留的逻辑字节数计算；物理去重节省的空间不会增加
逻辑配额。保留策略绝不会移除当前 head。

## 存储与安全

默认最大块大小为 4 MiB。先做 zlib 压缩，再使用 cryptography 库的
AES-256-GCM 加密；每次写入都使用随机的 96 位 nonce。每工作区密钥使用 HKDF
派生；关联数据（associated data）绑定工作区、明文 SHA-256 和大小。解压有
上界限制，并会校验明文摘要。持久化的主密钥需要受保护的备份；生产级 KMS 与
密钥轮换需要单独设计。

对象名称是服务端派生的不透明哈希。原子临时写入和重命名先于元数据发布；失败
的元数据提交会留下可回收的孤儿数据。引用计数跟踪每一个保留的修订版本。进行
中的会话固定（pin）其声明的块。GC 在删除未引用数据之前需要一个元数据事务和
宽限期。本地冷目录用于演示显式的归档/恢复语义；它不提供云端持久性，也不对应
Glacier 的定价/延迟。

## 同步与通知

事件携带不可变的修订版本 ID，因此分页的订阅源可以精确重放各个状态。每个设备
都有已确认（acknowledged）和已投递（delivered）两个游标。确认单调递增，且
不会超过投递。客户端只有在文件系统操作成功后才持久化本地进度，然后再进行
确认；重试可以重放事件。下载缓存键包含工作区和摘要。本地脏文件在被远程替换
之前先复制到冲突路径；本地删除会变成服务端的条件墓碑。

只有经过认证的成员才能读取元数据或其文件所引用的块。每个请求都会检查 ACL。
撤销会阻止后续的服务端读取，但无法抹除之前已下载的数据。路径会拒绝目录穿越、
平台保留名称和符号链接；客户端检查路径包含关系并保留其状态目录。原型假设
每个设备文件夹只有一个客户端进程，并且没有恶意本地进程与文件系统操作竞争。
HTTP 绑定到回环地址；远程使用需要 TLS。

## 限制与验证

固定大小分块复用未变化的按块对齐数据，而不是 rsync 式的字节移动。SQLite/
本地存储提供了可运行的持久化参考；多主机高可用、复制对象存储、有界的生产
事件保留和移动端文件监视器仍是待扩展项。客户端提供显式的推送/拉取与轮询，
而不是宣称拥有平台原生的后台文件系统监视器。

测试覆盖加密、中断上传、并发编辑、回滚、数据损坏、ACL 撤销、配额、事件重放、
安全 GC 以及真实的 HTTP/设备进程。报告会说明测试数据大小、并发度和实际传输
的字节数。

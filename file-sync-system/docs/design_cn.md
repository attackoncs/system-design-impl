# 设计：文件同步系统

本轮核对和验证见 [第16章记录](chapter16-review.md)。新增 schema/manifests/paths/
lifecycle/notifications 模块，分离存储模式、声明、路径、操作所有权和持久通知。
简单上传复用分片状态机，历史查询支持条数上限；自动 SyncWatcher 串行扫描和轮询，
持久绑定工作区，设备目录有 OS 独占锁，默认扫描上限 10,000 项、磁盘块缓存 64MiB。
扫描跳过 (size, mtime_ns) 与上次哈希核实值相同的文件（客户端逐文件保存；远端更新
后或升级前旧行为 NULL 即需哈希），2 秒内修改的文件和显式 push 总是重新哈希；
同大小且同 mtime 的编辑是 stat 检测公认的取舍。
它不是原生文件监控器，冲突保护副本保持本地。

大块压缩/加密、全文件校验和下载在全局锁外执行，最终事务复核会话、权限与对象。
不可变清单按修订号缓存（最多128项/8MiB编码输入），仍查当前 ACL/文件头。通知
增加 pending/cancelled，未完成内容仍隐藏；整页应用后才持久游标/确认。空闲长轮询
仅读，返回前写一次交付位置并复核 ACL；本地条件唤醒和跨进程定期读结合。

HTTP 为前台请求保留槽位，严格 framing/JSON、绝对套接字期限、停服取消轮询并
等待请求/定时器。Drive 关闭先唤醒轮询并等待已接受 I/O，不能强制取消系统文件或
数据库等待。归档、恢复、写入、GC 使用同一组跨进程块锁；有界解密/解压、验证后
复用对象。过期状态先提交再做物理删除，失败不恢复已过期预留；宽限并非持久 pin。
SQLite 元数据写和保守 GC 仍串行，云复制、数据库高可用及生产容量未验证。

## 组件与一致性

认证 HTTP API、块存储、元数据状态机和设备客户端是相互独立的模块。SQLite WAL
保存身份标识、工作区 ACL、文件、不可变修订版本、可恢复会话、块/引用计数以及
持久化的用户事件。BEGIN IMMEDIATE 在参考实现的多个服务进程之间串行化状态
变更。没有任何元数据读缓存会掩盖写入或 ACL 变更。长轮询基于持久化事件日志和
周期性的数据库读取，因此即使丢失唤醒也不会丢失变更。

## 上传与修订版本

客户端对固定大小的块计算哈希，并按顺序声明其摘要/大小清单。会话 ID 和调用方
请求 ID 标识可重试的工作。同一工作区内的块可以复用，而互不相关的工作区无法
相互探测对方的哈希。块字节先经过校验、压缩和加密，然后才提交其元数据。发布
操作在锁外校验块与完整文件哈希，最终事务复核会话、权限、块存在性和预留配额；
修订版本、head、引用和通知一起提交。未完成的上传绝不会以可下载文件的形式出现。

期望的基础修订版本（expected base revision）为编辑设置围栏。首个匹配的发布
获胜。过期的写入者会收到一个独立的冲突文件，其唯一路径由服务端生成；其会话
会记录该结果，因此重试不会创建多个副本。过期的删除请求会被拒绝。修订版本和
墓碑（tombstone）在显式执行保留清理之前一直可用。配额按保留修订版本（包括
冲突副本）加上进行中上传预留的逻辑字节数计算；物理去重节省的空间不会增加
逻辑配额。保留策略绝不会移除当前 head。保留字节为 `users.used` 计数器，在
commit/prune 事务内同步更新（打开旧库时一次性回填），上传准入不再汇总全部修订。

## 存储与安全

默认最大块大小为 4 MiB。先做 zlib 压缩，再使用 cryptography 库的
AES-256-GCM 加密；每次写入都使用随机的 96 位 nonce。每工作区密钥使用 HKDF
派生；关联数据（associated data）绑定工作区、明文 SHA-256 和大小。解压有
上界限制，并会校验明文摘要。持久化的主密钥需要受保护的备份；生产级 KMS 与
密钥轮换需要单独设计。

对象名称是服务端派生的不透明哈希。原子临时写入和重命名先于元数据发布；失败
的元数据提交会留下可回收的孤儿数据。引用计数跟踪每一个保留的修订版本。进行
中的会话固定（pin）其声明的块。GC 在删除未引用数据之前需要一个元数据事务和
宽限期。本地冷目录用于演示显式的归档/恢复语义；它不提供云端持久性，也不对应
Glacier 的定价/延迟。

## 同步与通知

设备传输在一个绝对套接字期限内用有限 read1 读取；到达EOF后还检查声明的
Content-Length是否已收齐，完整JSON前缀或块数据不能代替响应完整性。固定长度或
chunked正文截断统一抛OSError，自动同步沿现有有上限退避重试。失败的changes响应
不会推进本地游标或确认；不带Content-Length的合法关闭定界响应仍可接受。连接、
响应和期限定时器在成功/失败时都释放。

### 事件保留与重新快照

策略：按工作区裁剪早于 `event_max_age`（默认30天）的事件以及超出
`event_max_per_space`（默认10万行）的行，任一上限可关闭。`event_spaces(space,
floor, retained)` 维护行计数与下限。裁剪只删除某工作区最旧的前缀（`events(space,
seq)` 索引，`DELETE ... WHERE space=? AND seq<=?`），并在同一事务抬高 floor，因此
"seq <= floor" 恰为已裁剪集合。每次追加最多裁剪本工作区 `max(64, 2×新增行数)` 行
（摊还，无 COUNT 扫描）；`cleanup`/`expire_events` 清扫已空闲的工作区。日志高水位
取自 `sqlite_sequence`，即使全部行被裁剪游标仍有效。旧库一次性增加
`events.created`（取打开时间）并回填各工作区计数。

一致性：`changes` 在同一读事务内读取高水位、用户所在工作区的 floor 与事件。任一
floor 大于游标时返回空事件、原游标和 `resnapshot: true`；否则游标之后的事件在该
快照中均仍存在，不会投递缺口。`POST /snapshot` 在同一 `BEGIN IMMEDIATE` 事务内读取
当前 head、高水位 H 并记录 H 的投递：≤H 的事件均已体现在 head 中，>H 的事件要么
仍保留，要么被裁剪后使 floor 超过 H 而再次触发重新快照。客户端只对比本地版本更新
的 head 走常规 `apply`（本地脏文件变为 local-conflict 副本，墓碑删除本地文件），
然后持久化并确认 H；失败则保留旧游标。检查偏保守：用户任一工作区的裁剪都可能
触发一次低成本的重新快照（版本未变的文件不发请求）。单个快照响应受客户端4MiB
JSON上限约束（约数万文件）。

事件携带不可变的修订版本 ID，因此分页的订阅源可以精确重放各个状态。每个设备
都有已确认（acknowledged）和已投递（delivered）两个游标。确认单调递增，且
不会超过投递。客户端只有在文件系统操作成功后才持久化本地进度，然后再进行
确认；重试可以重放事件。下载缓存键包含工作区和摘要。本地脏文件在被远程替换
之前先复制到冲突路径；本地删除会变成服务端的条件墓碑。

只有经过认证的成员才能读取元数据或其文件所引用的块。每个请求都会检查 ACL。
撤销会阻止后续的服务端读取，但无法抹除之前已下载的数据。路径会拒绝目录穿越、
平台保留名称和符号链接；客户端检查路径包含关系并保留其状态目录。OS 锁保证
每个设备文件夹只有一个客户端进程，并且没有恶意本地进程与文件系统操作竞争。
HTTP 绑定到回环地址；远程使用需要 TLS。

## 限制与验证

固定大小分块复用未变化的按块对齐数据，而不是 rsync 式的字节移动。SQLite/
本地存储提供了可运行的持久化参考；多主机高可用、复制对象存储、事件保留的
持续压测和移动端文件监视器仍是待扩展项。客户端提供显式的推送/拉取与轮询，
而不是宣称拥有平台原生的后台文件系统监视器。

测试覆盖加密、中断上传、并发编辑、回滚、数据损坏、ACL 撤销、配额、事件重放、
安全 GC 以及真实的 HTTP/设备进程。报告会说明测试数据大小、并发度和实际传输
的字节数。

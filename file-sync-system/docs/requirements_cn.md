# 需求：文件同步系统

来源：根目录 System Design Interview.md，第 16 章，设计 Google Drive。

- R1. 上传/下载最大 10 GiB 的任意二进制文件，包括空文件。将文件拆分为有界
  块（默认 4 MiB）；不缓冲整个大文件。
- R2. 经过认证、可恢复的上传会话，带请求 ID、SHA-256 校验和、账户/工作区
  范围的去重，以及在所有块存储并校验完成之后的原子发布。冲突的重试必须失败。
- R3. 压缩块并使用 cryptography 的 AES-GCM 进行静态加密，采用随机 nonce 和
  经认证的命名空间/哈希/大小元数据。检测密文损坏。
- R4. 不可变修订版本、基于基础修订版本的乐观写入、保留并发编辑结果的冲突
  副本、墓碑、修订版本列举与恢复。
- R5. 由所有者控制的工作区读写共享、即时的服务端撤销，以及配额执行（包括
  保留的修订版本和进行中的上传）。
- R6. 按用户划分的事务性变更事件、长轮询、持久化设备游标、显式确认，以及
  断开连接/服务端重启后的重放。
- R7. 真实的文件系统客户端使用安全的相对路径、原子文件替换、持久化的本地
  状态和块缓存；只传输缺失/被修改的块，保留未同步的本地编辑而不覆盖它们。
- R8. 引用计数、修订版本保留、保守的孤儿/会话清理，以及显式的冷层归档/恢复
  行为，不宣称真实的 Glacier 集成。
- R9. 可重复的正确性/故障测试，以及独立的网络/进程演示。测量同步延迟、块
  复用和传输字节数。

参考实现的持久化采用本地 SQLite WAL 和加密文件系统对象。不宣称元数据高可用、
跨区域复制、千万用户规模、商业移动客户端、文档协同编辑或生产级 TLS/KMS。
这些属于部署层面的扩展，而不是被默默模拟出来的功能。

# 文件同步验收与网络测量

## 2026-11-19 提交开销与持续恢复

| 单机实验 | 结果 |
| --- | --- |
| 20,000 个已有文件，空文件同路径修订，预热 3 次后取 25 次提交中位数 | 全表检查 24.20 ms，索引检查 0.205 ms |
| 8,000 个已有文件，新建四级路径空文件，SQLite 每 100 条虚拟机指令计数 | 约 97,400 → 1,500 条指令，两个冲突查询分支均使用索引 |

持续实验使用 5 个独立 Drive 连接和一个工作区，按条数保留最后 40 个事件。两个写者各自更新一个 1 KiB 文件，每次上传后等待 70 ms。两个在线订阅者连续长轮询并确认，另一个文件系统设备每 2 秒经回环 HTTP 拉取。写入停止后对账所有修订、设备记录、文件摘要和事件序号。两位写者在同一工作区的不同文件上持续提交 62 秒，共产生 1,702 个唯一修订和 3,404 条事件。两位在线设备完整收到连续序列。离线设备完成 31 次快照恢复，三个设备的投递和确认游标最终都为 3,404，文件内容与最后修订一致。事件表计数与实际行数均为 40，SQLite quick_check 通过。

## 2026-11-18 离线恢复与增量传输

原进程示例在 12,288 字节的文件上只下载发生变化的 4,096 字节，设备复用其余 8,192 字节。API 进程重启后，从持久游标继续同步。复现时在项目目录运行 `python tools/benchmark.py --output benchmarks/review-2026-11-18.json`，本机回环地址须直连。[原始测量](review-2026-11-18.json)

另用临时 SQLite 数据库建立 1,600 个长 Unicode 路径的空文件修订，保留最后一个事件。从空设备目录调用实际 HTTP pull，全部文件落盘。原单响应 4,629,810 字节，新协议 7 页，最大一页 743,852 字节，末次本地游标 1,600。这次实验衡量元数据恢复，文件内容传输另由上述非空文件示例验证。[完整测试与实验范围](verification-2026-11-18.json)

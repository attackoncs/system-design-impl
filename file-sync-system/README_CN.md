# 文件同步系统

第 16 章 Google Drive 的参考实现：分块上传、断点续传、工作区内去重、压缩与
AES-256-GCM 存储加密、修订历史、增量同步、冲突副本、分享撤销和持久化通知。

在本目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -e '.[dev]'
.\.venv\Scripts\python -m pytest -q
.\.venv\Scripts\python examples/network_demo.py
```

示例启动真实 API 进程及独立设备进程，验证三块文件同步、中间块修改后只传输变化
块，以及服务重启后设备游标恢复。退出时停止自己的服务并清理临时目录。

持久运行和所有接口参数见[英文说明](README.md)。服务默认每块 4 MiB，文件上限
10 GiB，配额包含保留的修订及正在上传的预留空间。首次上传和重试必须保持请求 ID；
旧版本并发更新生成冲突副本，旧版本删除被拒绝。目录按相对路径建立，不含文档协同编辑。

客户端通过显式 push/pull 同步，本地 `.sync` 保存进度和明文块缓存。服务端对象
真实压缩加密，元数据保留主密钥；这不是端到端加密，需保护数据库及密钥备份。
服务端每次请求检查分享权限，撤销后拒绝新下载；无法远程擦除已有离线副本。

修订保留和垃圾回收显式执行；正在上传的块受保护。归档/恢复接口使用本地冷目录
演示，尚未接入真实云归档。默认仅本机 HTTP，远程部署需要 HTTPS。

当前为 SQLite/本地块存储参考实现，未接入跨地域复制或元数据高可用。
客户端不是原生文件监控器，建议每个设备目录只运行一个进程；路径重叠的工作区
应使用不同设备目录。生产需要事件保留、重新快照、缓存容量策略及监控。

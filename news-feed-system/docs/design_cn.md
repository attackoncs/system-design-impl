# 第12章设计

`NewsFeedAPI` 组合发布、读取、存储、策略、队列与后台任务；详细章节对应关系和验证证据见[章节核对](chapter12-review.md)。

## 发布

HTTP 鉴权后，PostService 复制并校验请求，按令牌确定作者、检查限流，将帖子和待分发标记写入同一源事务。API 返回接受的 ID，由同一事件循环的后台 dispatcher 分类作者、应用可见性规则并分发。独立使用 PostService 时，默认仍在 publish 中调用分发，以保留库调用兼容性。

普通作者分批进入队列；明星作者保留源帖子，由读者按需拉取。通知模块以固定数量协程复核当前关注与可见性，保存本地去重记录。失败 outbox 轮转重试，避免最早的失败记录阻塞后续任务。

## 读取

Feed 缓存仅保存 ID 和时间索引，按时间、帖子 ID 排序和去重。读取服务维护一页大小的候选集合，合并普通作者推送与明星索引。冷窗口、关注/静音/分类变化、到期窗口和历史分页会并发回源；普通作者的完整热窗口复用推送缓存。默认最多16个固定协程，不为每个关注对象创建任务。

覆盖记录同时保存设置签名、最旧完整键和不因刷新而延长的到期时间，避免缓存中历史空洞或频繁读取阻止修复。游标采用时间及 ID 的 keyset，返回前再检查关注、静音和分享名单。内容、作者资料缓存缺失时回源；互动与计数来自本地缓存，媒体地址交给客户端加载。

## 存储与并发

SQLite 的帖子、资料、关注和静音适配器与领域服务分离。帖子 ID 不可覆盖；缓存与存储公开返回可变列表的快照。缓存变更使用线程同步，社交加载使用条带锁、合并请求和失效栅栏。

队列的待处理、延迟和执行中任务共同占用容量；确认凭据拒绝旧任务，部分成功重试依赖 Feed 去重。worker 取消归还领取，异常不终止整个池，最终失败进入有界死信缓冲。API 并发启动/关闭共享生命周期锁和清理任务，关闭期间拒绝新发布，等待已接受请求并回收 worker。

默认队列10000、worker4、批次100、重试3次、死信保留100；每用户 Feed500、修复周期30秒、默认页20且最多100、关注范围5000。配置采用不可变数据类并严格校验整数及有限正数。

## 一致性与扩展

outbox 确认交给本地分发阶段，不确认持久 worker 完成；进程退出后的内容从源修复，主动通知没有持久送达承诺。普通作者热 Feed 最终一致，游标是当前数据视图。内存源、计数、互动、令牌和限流窗口随进程退出丢失；跨进程写入的静音快照与社交缓存需要刷新/TTL。

PostStore/UserStore 协议和 Authenticator/SocialGraph 接口支持替换适配器。共享缓存/持久 broker、一致性哈希分片、全局配额、复制、多机房、真实推送以及媒体/CDN 均需部署集成，未验证千万日活容量。英文[设计图](design.md)展示发布与读取的数据关系。

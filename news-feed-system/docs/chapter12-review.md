## 软件工程与并发处理

新增组合入口 `api.py`，领域服务依赖存储/鉴权接口；SQLite、内存适配与 HTTP 生命周期各自独立。读取逻辑按候选合并、缓存、分类、修复和组装拆分。接受请求和公开缓存返回值复制可变列表，调用者不能修改已经接受的媒体或分享名单。

后台 outbox 每次最多读取100条，失败记录移到后续轮次，避免最早失败的100条一直阻塞新帖子。同一服务的发布与恢复共用分发互斥锁；跨实例仍采用至少一次语义。作者拉取默认16个固定任务，并保留一页大小的合并候选，不为每位作者创建协程或收集全部历史。

worker 默认重试3次，退避从0.05秒起、上限30秒，最终失败进入最多100条的诊断死信缓冲，并累计失败计数。`WorkerPool.stop()` 完成已领取任务并保留未领取任务，默认30秒后取消慢任务并归还；需要全部排空时先调用 `queue.join()`。API 并发启动/关闭共享生命周期同步，关闭时拒绝新发布并等待已接收的发布，取消关闭调用者仍保留清理任务。

## 可靠性边界

- SQLite 使用 WAL、FULL synchronous 和短事务；帖子接受与待分发标记原子提交。进程在提交后退出，源帖子和待分发记录可重开读取。
- outbox 的完成表示交给本地分发/通知阶段，不是持久化 worker 完成。完成后进程退出可能丢失内存队列、死信和通知；Feed 内容经冷读取/修复重建，主动通知不承诺恢复。
- 普通作者热 Feed 最终一致；尚未推送的帖子可延后到 worker 完成或下一次源修复。游标按当前源数据分页，不是跨页数据库快照。
- 默认内存源保留全部历史，进程退出丢失；Feed 容量是每用户限制，不是全局内存上限。互动、计数、令牌和限流窗口也只在本进程内。
- SQLite 静音数据启动加载为本地快照；其他实例修改后需要 `reload()`。社交缓存本地变更立即失效，外部写入受 TTL 约束。多个 API 实例不提供全局限流或即时缓存一致性。
- 通知仍为本地模拟记录；媒体为外部地址。没有部署共享队列/缓存、CDN、分片或跨机房复制，也没有生产吞吐与延迟承诺。

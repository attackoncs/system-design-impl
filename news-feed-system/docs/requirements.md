# Chapter 12 requirements: News Feed System

Reviewed against chapter 12, “Design A News Feed System”, in the repository's `System Design Interview.md`. Updated 2026-10-29. This document specifies the executable local reference and separates it from the book's deployment discussion. The [Chinese version](requirements_cn.md) uses the same requirement IDs; [tasks](tasks.md), [design](design.md) and [chapter audit](chapter12-review.md) provide implementation and verification context.

## Scope and status

The two primary flows are publication and reverse chronological retrieval. Web/mobile clients use an HTTP adapter; the library composes interchangeable storage/authentication adapters, local caches and asynchronous fanout workers. A social relationship is represented as a directed follow; friendship can be represented by reciprocal follows.

The book's 5000-friend and 10-million-DAU figures are design assumptions, not measured capacity. The default read scope is 5000 followed authors; the SQLite graph also enforces that configured limit on writes. An in-memory or custom graph is not a distributed graph database. “Implemented locally” below never means a production service, replicated system or external provider has been deployed.

| REQ-12-01 | Expose POST and GET `/v1/me/feed`. Authenticate both operations. | REQ-12-06 | Use hybrid fanout. Ordinary authors push batches of post IDs to eligible followers through the queue; authors with follower count at or above the configured celebrity threshold skip push and are pulled from the indexed source during retrieval. | REQ-12-07 | Apply one mute/selective-sharing policy during fanout, feed retrieval and local notification recording. A selective list of `None` means all eligible followers; an empty list means no recipients. Recheck current relationships and visibility after asynchronous loading and before returning entries or recording notifications. SQLite mute preferences survive reopening. | Implemented locally: `policy.py`, `fanout_service.py`, `news_feed_service.py`, `notification_service.py`; `test_mute_policy.py`, `test_notification_reliability.py`, `test_chapter12.py`. |
| REQ-12-08 | Queue capacity must count pending, delayed-retry and claimed jobs together. Claims have receipts that reject stale acknowledgement/retry. Delayed claims must work across the supported Python versions, including Python 3.9/3.10 timeout semantics. | Implemented locally: `queue.py`, `worker.py`, `news_feed_cache.py`; `test_queue.py`, `test_worker.py`, `test_worker_reliability.py`, `test_chapter12_queue_audit.py`. The queue, claims and dead letters are in memory. |
| REQ-12-09 | Keep a configurable number of feed IDs per reader, ordered by `(timestamp, post_id)` descending and deduplicated by post ID. Store IDs/author/time metadata rather than hydrated post/profile objects. Late or duplicate deliveries cannot displace newer entries incorrectly. | Implemented locally: `news_feed_cache.py`; `test_news_feed_cache.py`, `test_worker_reliability.py`, `test_chapter12.py`. Per-reader capacity is not a global memory bound. |
| REQ-12-10 | Merge ordinary push and celebrity pull candidates into a bounded page. Use validated keyset cursors containing time and post ID, so newer insertions do not shift older page positions. Hydrate only visible candidates and return a continuation cursor when another visible entry is available. Concurrent hydration must preserve sorted output order. Pages represent current data rather than a cross-page database snapshot. | Implemented locally: `news_feed_service.py`; `test_chapter12.py`, `test_http.py`, `test_chapter12_read_audit.py`. |
| REQ-12-11 | Repair cold, expired, changed-policy/classification and historical feed windows from the authoritative per-author index. Do not stop at the first full batch of private posts. Warm ordinary-author windows can reuse pushed IDs; frequent refreshes must not postpone the repair deadline indefinitely. Bound both the coverage ledger and concurrent author lookups. | Implemented locally: `news_feed_service.py`, `storage.py`; `test_chapter12.py`, `test_cache_reliability.py`. Repair is read-triggered, not a periodic preloader. |
| REQ-12-12 | Connect the five cache groups described in the book: feed IDs; hot/normal content; follower/following graph; per-user actions; counters. Hydrate author name/avatar, post text/media, action state and counters. Content/profile misses load from their source; missing author profiles use an ID-based placeholder. Fixed worker sets bound cached-ID loading and hydration too; concurrent profile misses for one author coalesce behind bounded striped locks. Public cache values must not let caller mutation alter stored state. | Implemented locally: cache modules and `news_feed_service.py`; `test_action_cache.py`, `test_counter_cache.py`, `test_user_cache.py`, `test_cache_reliability.py`, `test_chapter12.py`, `test_chapter12_read_audit.py`. Engagement state is process-local. |
| REQ-12-13 | Notify eligible followers that new content is available, using per-recipient bounded and deduplicated local records. Recipient validation must use a fixed worker set instead of creating one task per follower. | Local simulation implemented: `notification_service.py`; `test_notification_service.py`, `test_notification_reliability.py`. Real mobile/browser push, durable notification recovery and provider receipts are not implemented. |
| REQ-12-14 | Own background work explicitly. An API instance belongs to one event loop; concurrent start/stop calls share lifecycle synchronization. Shutdown rejects new publications, waits for admitted publication work and stops owned recovery/workers. Cancelling a shutdown waiter must not abandon shared cleanup. HTTP request threads submit to a shared loop instead of creating per-request loops. | Implemented locally: `api.py`, `concurrency.py`, `http.py`, `worker.py`; `test_api_lifecycle.py`, `test_worker_reliability.py`, `test_http.py`, `test_chapter12.py`. |

Inject store/authentication/graph adapters; validate immutable configuration at construction; offload blocking storage work from the event loop. Bounds are local; they do not provide cluster-wide admission control. |

## Defaults and invariants

| Setting | Local default / meaning |
| --- | --- |
| Publication quota | 10 posts per author per 3600-second sliding window. |
| Celebrity threshold | 5000 followers; `>=` selects pull mode. |
| Fanout | 4 workers; batches of 100 recipients; queue capacity 10000 jobs. A configured queue capacity of 0 explicitly selects unbounded mode. |
| Worker failure | At most 3 retries after the initial attempt; initial delay 0.05 seconds, capped backoff; diagnostic dead-letter retention 100. |
| Feed/read | 500 IDs per reader; page size 20, maximum 100; author-query concurrency 16; read-repair window 30 seconds; coverage ledger 5000 readers. |
| HTTP adapter | 32 concurrent request handlers; 1 MiB body; 10-second connection timeout; 15-second application request deadline. Constructor options can change these. |

`queue.join()` covers admitted queue work, including claimed work. It does not include pending source outbox rows that have not entered the queue. SQLite is the local authoritative source; caches can be rebuilt from it. Tokens, quotas, actions/counters, queue state and local notifications do not become durable by choosing SQLite mode. If the process exits after dispatch but before a worker finishes, subsequent reads can reconstruct feed content; proactive notifications have no durable-delivery guarantee.

## Deployment and operations requirements

| ID | Requirement | Current boundary / acceptance for future work |
| --- | --- | --- |
| REQ-12-16 | Observe request throughput, feed-refresh latency, queue pressure and failures without unbounded metric labels or retained payloads. | Local request observation is implemented in `metrics.py` and `NewsFeedAPI.metrics()`, covered by `test_chapter12_metrics.py`: publish/retrieve requests, in-flight/success/failure/cancellation counts, lifetime duration count/total/mean/max and recent QPS. Queue diagnostics/logs support investigation. Production exporters, latency distributions, dashboards and alerts remain integrations; engagement counters are not service metrics. |
| REQ-12-17 | Serve media via a CDN and send real push notifications. | URLs and local notification records are implemented. Acceptance needs configured media upload/origin/CDN and provider adapters, delivery/error handling and tests against owned integration endpoints. |
| REQ-12-18 | Distribute load/state with stateless web nodes, shared cache/broker, sharding, replication/read replicas, global quotas and multiple data centers. | Not deployed. Acceptance needs defined consistency/failover contracts, shard routing/migration, durable broker acknowledgements and failure/recovery tests; a Python interface or local SQLite database alone does not satisfy this. |
| REQ-12-19 | Validate the book's 10-million-DAU scale and latency objectives. | Not measured. Acceptance requires a stated workload, peak distribution, hardware, durability settings, errors and latency percentiles. No production throughput/latency claim follows from the unit suite. |

`api.metrics()` measures API operations only: publish latency ends at source acceptance, and HTTP requests rejected before reaching the API are excluded. Duration aggregates use seconds and include completed successes, failures and cancellations. Recent QPS uses the current and previous 59 one-second buckets divided by 60, including during startup; it is a bucketed estimate rather than an exact sliding window. Snapshots are independent and can be collected from a monitoring thread. Only fixed `publish`/`retrieve` labels are accepted; no tokens, user IDs, content or individual latency samples are retained.

The book's SQL/NoSQL, vertical/horizontal scaling, replication and consistency-model points are design tradeoffs, not a requirement to deploy every alternative simultaneously. [Open tasks](tasks.md#deployment-and-operations-backlog) track concrete next work.

## Verification contract

Run the chapter suite separately from other chapters, from `news-feed-system`:

```sh
python -m pip install -e ".[dev]"
python -m pytest tests -q -p no:cacheprovider
```

For an uninstalled checkout, set `PYTHONPATH` to the absolute project `src` directory so subprocesses inherit the source path. The Windows event loop and local HTTP tests need loopback socket access.

The [chapter audit](chapter12-review.md) records the final result of the current review. This document does not substitute a previous run's count for a fresh run. Tests use local files/subprocesses/loopback HTTP and do not send third-party notifications or validate distributed deployment capacity. Changes to requirements must update their linked tasks, corresponding Chinese documents and acceptance evidence.

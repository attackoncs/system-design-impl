## 已修复的问题

旧Merkle每次写入重算全部桶的父哈希，且修复一次返回所有差异数据。
现在保持原哈希格式，只重算叶到根；1024桶的一个稀疏差异只比较21个节点。
新RPC每批最多64个元数据节点，数据页最多128条/2MiB且遵守通道限制。
root变化拒绝该页；同时核对记录摘要与索引，防止存储已可见但索引尚未发布
的提交被标记为旧root；本地放置固定，先拉后推，失败后可重复合并。
64KiB实际通道中，旧264512字节响应失败，新协议5页完成196608字节应用数据，
包括反向墓碑同步；第二轮根一致时数据页0。

旧asyncio.to_thread被取消后线程仍继续，外层锁却会提前释放；现在本地提交
排空后才传播取消。SSTable原先只flush，现在fsync临时文件、原子替换并按
平台同步目录后才截WAL；压缩持久化后退役旧文件。flush失败也关闭WAL。
损坏最终表改为拒绝启动，不能静默忽略而报告缺失数据。

原先物理时间回退时MemTable会忽略新的因果记录；文件创建时间排序也会让
重启/压缩选错。现在内部物理时间nextafter递增，读取与恢复跨候选层比较。
已用回退100→10、强制flush/压缩、墓碑与重启验证；增加读开销如实实测。
提交后flush失败仍可能留下已生效的数据，索引会按可见记录刷新。

旧hint删除只看行ID；两个实例交错投递时SQLite可能复用ID，使迟到ACK误删
新hint。现在匹配id/target/key/原blob，并串行同对象投递；已测真实SQLite复用。
本地/远端记录拒绝重复JSON、未知字段、负/非有限时间及超int64计数。

## 尚未完成与兼容风险

1. 没有负载驱动的节点资源供给/回收、安全缩容完成屏障、拓扑epoch/共识。
2. 跨机房只有故障域选择，未提供TLS/认证、WAN分区/机房仲裁或真实容灾验证。
3. SSTable仍缓存整文件，恢复/Merkle索引和压缩仍有全量内存开销；分页网络
   不代表已支持海量数据。尚无流式压缩、磁盘配额或生产容量证明。
4. 树尚未按节点对共有职责分片；N小于成员数时非共有桶可能重复比较。
   连续写入可能使root固定视图反复中止，没有持久桶内续传游标/全轮硬截止。
5. W+R>N不是线性一致；失败/取消可能已提交部分副本。没有业务幂等键、事务、
   安全墓碑GC或hint DLQ。Windows目录同步/真实断电持久性未验证。

磁盘envelope格式仍为1，新的严格校验可能拒绝此前异常记录；不要清空原数据。
旧裸值格式仍须导出/导入。两个修复RPC需节点同步升级，旧全量RPC仅保留兼容。
单节点README改为1/1/1，多个节点明确独立三目录，修正原示例可能共享WAL路径。

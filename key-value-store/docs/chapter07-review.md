# 第 07 章实现核对与运行边界

本次以仓库 `System Design Interview.md` 第 07 章为依据，检查从 `KVNode` 启动到真实 gRPC、磁盘恢复的执行链。原有组件测试通过不能证明这些组件已经连接正确。本章仍有下列未完成项，不能标记为“原书全部实现”。

## 已补齐的执行链

| 原书内容 | 当前实现与证据 |
| --- | --- |
| put/get、小值、持久化 | 值不超过 10 KiB；WAL、MemTable、SSTable 保存包含值、向量时钟、时间戳的同一条记录。恢复时重建 Merkle 索引。 |
| N 个不同物理副本 | 一致性哈希去重后选取；`ReplicaPlacement` 统一协调请求与修复的副本选择。 |
| 不同硬件容量的虚拟节点 | `NodeConfig.node_virtual_nodes` 配置每个节点的 vnode 数量；全部节点须使用相同配置。默认仍用 `virtual_nodes`。 |
| 跨数据中心放置 | `node_data_centers` 映射节点到故障域，优先选取不同域，域不足时按环顺序补足。未配置的节点视作同一个未知域。已测试选择算法；未进行真实跨机房容灾演练。 |
| 可调 N/W/R | `ReplicaCoordinator` 并发使用专用 `ReadReplica`/`MergeReplica`，达到 R/W 后返回；不会递归调用面向客户端的协调 RPC。慢副本由协调器跟踪直到完成或关闭。 |
| 向量时钟及并发冲突 | `ReplicaRecords` 在 64 个条带锁下合并因果版本，保留未被支配的 siblings；删除是携带时钟的 tombstone，区别于空字节值。客户端合并冲突时钟再写可解决冲突。 |
| gossip 与失败检测 | 实际交换成员及监听地址并更新哈希环；启动后持续重试种子。重启节点看到自己的旧 heartbeat 后推进计数，避免一直落后于其他节点记忆。活动节点必须具有唯一 ID。 |
| sloppy quorum 与 hinted handoff | 疑似故障的原副本仍保留在偏好列表，使用后续存活节点替代；SQLite 保存原目标及完整版本，确认投递后按行 ID 删除；分页游标避免离线积压阻塞后续 hint。 |
| Merkle / anti-entropy | 桶哈希包含带长度的键和值摘要，空叶参与二叉父节点哈希；周期任务通过真实 RPC 双向同步差异桶，只向应持有键的副本合并数据。 |
| 资源与并发 | 请求在第一次 await 前预留复制容量，包含等待同键写锁的请求；256 个容量单位，保守计入在途任务。停止时取消并等待请求、复制和种子任务，关闭通道及存储；部分启动失败也清理。 |

代码职责：`replication/records.py` 管持久版本及合并；`replication/service.py` 管真实网络 quorum；`cluster/placement.py` 管副本位置；`cluster/repair.py` 管持久 hint 和修复；`node.py` 管组装及生命周期。原 `RequestCoordinator` 保留旧组件调用接口，`KVNode` 注入记录层后使用新执行链；旧 mock 路径不作为真实集群实现证据。

## 语义和兼容性

- `W + R > N` 仅表达稳定副本集合上的 quorum 交集，不代表线性一致性；并发版本、sloppy quorum、成员变化会影响结果。`ALL` 也不是事务或共识协议。
- 写入协调节点先保存本地版本，即使它不在 N 个主副本中，因此可能多保留一份数据。未达到 quorum 的写入可能已在部分节点生效，客户端不能把失败解释为回滚。
- 删除记录不会随普通 LSM compaction 消失；未提供安全 tombstone GC。向量时钟长度遵循 `vector_clock_max_entries`（1–256）；运行时截断保留协调节点自身计数，以便重启后递增，但截断其他条目仍可能丢失因果信息。重复客户端写入没有业务幂等键。
- 每条内部记录最大 1 MiB、最多 256 个 siblings；超限拒绝写入，需要客户端解决冲突。输入拒绝不会自动丢弃旧版本。
- 磁盘记录格式改为版本化 envelope。旧版本仅存裸值的目录不能直接启动，本次没有自动迁移或清空数据；请保留原目录，使用旧版本导出后向新实例导入。导出导入无法恢复旧版从未保存的向量时钟。
- 新增副本 RPC 和 tombstone 字段要求所有节点同步升级。Python 最低 3.10，gRPC >= 1.84.0，protobuf >= 7.35.1 且 < 8；开发生成工具固定为 grpcio-tools 1.84.0。
- 在项目目录执行 `python tools/generate_proto.py` 可重新生成绑定并修正包内相对导入。生成文件不手工实现业务逻辑。

## 原书尚未完整覆盖的部分

1. **负载驱动的自动扩缩容**：没有监控驱动的资源供给/回收控制器，没有安全下线和数据迁移完成屏障。发现新节点、配置 vnode 和周期修复不能替代这一功能。
2. **完整 Merkle 网络遍历及大数据修复**：本地 root 是二叉树哈希，网络仍一次交换桶哈希及差异数据；没有逐层子树 RPC、分页或流式传输。单轮结果受 gRPC 消息大小限制，不适用于大差异集。
3. **跨机房运行保障**：只有故障域感知的放置算法；没有机房级仲裁、拓扑版本协议、传输认证/TLS 和真实跨区域部署验证。
4. **容量与吞吐证据**：恢复扫描和 Merkle 索引在内存中，SQLite hint 写入串行化，Merkle 根更新重算全部桶；本次没有证明海量数据容量或生产吞吐提升。

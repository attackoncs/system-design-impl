# Requirements: S3-like Object Storage

依据根目录《System Design Interview.md》第 25 章。范围包括私有桶、对象读写、版本/删除标记、排序列举、多部分上传、小对象聚合、多副本、修复与垃圾回收。原书 100 PB、六个九耐久性和四个九可用性为未验证的生产目标。

1. 桶名全局唯一，静态用户身份隔离，版本化始终启用。支持指定版本读取/移除和删除标记。
2. 数据块最大 256 KiB，SHA256 校验；默认至少 2/3 数据节点持久化确认才发布完整元数据。
3. 单 PUT 最大 4 MiB；多部分最多 64 个不可变部分，每部分最大 1 MiB，总对象最大 64 MiB/256 块。完成前验证总大小和 SHA256。
4. 持久化部分与完成意图，支持跨 API 重启续传和幂等完成；过期 active 可清理，completing 必须恢复而非猜测终止。
5. 不超过 64 KiB 的块聚合保存，偏移索引可重建；支持不完整尾部恢复和原子代际压缩。
6. 元数据按桶 ID+键分片，跨分片排序。分页冻结结果，签名 token 绑定用户/桶/查询，5 分钟有效。
7. 读回退、引用巡检、副本修复、版本保留和无引用回收；缺失元数据来源时停止 GC。
8. 真实六进程 HTTP 验证节点退出、逻辑磁盘不可用、字节损坏、发布中断、分页变更和恢复。
9. 上游HTTP错误体JSON无效或嵌套过深时，返回中性503而非直接断连。有效业务状态（如409）和客户端输入错误400保留，不自动重放写操作；结果未知的发布保留持久恢复意图。

不含 AWS 签名/协议兼容、纠删码、独立机房故障域、元数据复制/选主、在线分片迁移或 GB 级流式 IO。单目录不可用不等于真实硬件故障实验。

2026-10-26工程复核：本人桶列表、delimiter同层前缀列举、签名冻结混合分页、
严格私有manifest、有界共享读/发布与独占GC/删桶/快照、上传完成栅栏、持久化未知发布
恢复及节点代际回收。过载、不完整或损坏状态明确失败；验收覆盖远端延迟请求和确认丢失。
单机参考限制及未实现的生产HA、放置共识、GB流式仍须明确披露。

2026-11-05验收：基线137项/41.699秒，最终严格 **138项/41.769秒通过**，无跳过。
HTTP专项20项/2.422秒；新增1项含6个子场景，使用真实Service/Catalog/API与受控
元数据peer，检查仅一次删除标记发布请求及pending意图保留。该peer并未提交元数据，
不能据此声称验证真实提交后的确认丢失。唯一生产改动是HTTP错误体的递归异常保护，
元数据/数据并发保持不变。详见[源码与章节核对](open-source-review_cn.md)及

# 需求：Proximity Service（邻近服务）

来源：仓库根目录 `System Design Interview.md` 第 17 章。

## 契约（Contract）

- 返回请求球面半径内所有已发布商家，按距离升序、ID 次排序。半径单位为米，可选值：500、1000、2000、5000（默认）、20000。不得自动扩大半径。
- 校验有限纬度 [-90,90]、经度 [-180,180]；支持格单元边界、国际日期变更线和极点。
- 鉴权后的所有者可以创建、替换和删除自己的商家。幂等键必须跨重启持久化；相同键用于不同请求会产生冲突。
- 草稿变更在下一次 UTC 日发布时一起生效；主服务CLI运行自有后台发布任务，不要求读流量触发。搜索和公开详情使用同一份不可变版本。已删除/已迁移的记录在发布前仍然在旧版本中可见。
- 分类和 UTC 每周营业时间筛选为可选参数。分页将快照和查询绑定；发布后旧快照游标会产生冲突。
- 持久化草稿、快照、索引和重放记录；事务失败必须保证前一份完整版本可读。
- 有界 TTL 缓存保存 geohash 候选 ID 和版本化详情，绝不保存精确的用户坐标。
- 提供真实 HTTP 主服务、独立存储的拉取式副本和支持区域感知的读路由与故障切换。逻辑分片在本地实现；物理分片分发和云区域部署保留为显式扩展。

## 验收标准（Acceptance）

使用 Python 标准库、SQLite 和可重复的 unittest 测试。验证暴力空间查询等价性、重启行为、鉴权、重放、快照回滚、缓存 TTL、HTTP 错误、独立进程复制和副本故障。测量合成的密集/稀疏数据集，仅报告本地证据。原书设定的 2 亿商家、1 亿 DAU、5000 QPS 和生产可用性是设计目标，不作为本地验收声明。

## 边界（Boundaries）

开发令牌代表所有者身份；生产环境中需要额外的身份/租户验证、HTTPS、速率限制、备份、数据库高可用（HA）和法律审查，方可公开部署。请求不记录访问日志；查询坐标不持久化。幂等记录 7 天后过期，在后续写入中清理；旧快照在发布时移除。不收集位置历史。不存在公开的草稿读取 API。

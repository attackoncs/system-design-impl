# Design: Proximity Service

## Storage and publication
SQLite WAL stores drafts by business ID, owner, JSON body and tombstone; immutable public records and `(precision, geohash, shard, business_id)` indexes; active-version metadata and idempotency responses. Writes use BEGIN IMMEDIATE. Publication copies all live drafts and builds six prefix indexes in one transaction, swaps the version and removes the previous snapshot. Existing WAL readers retain the previous generation until their transaction ends. Automatic publication occurs on the first primary read or mutation after the next UTC date; a scheduler can also call the CLI. Today's first mutation freezes yesterday's drafts before accepting the new change. Publication is demand-driven, not a continuously running midnight job. An authenticated force endpoint supports demonstrations.

Public reads use one SQLite read transaction, binding metadata, candidates and hydrated objects to a single snapshot. Both cache types include lineage and version. A cache is process-local bounded LRU with monotonic TTL; old entries cannot leak into new snapshots. Detail reads use published data, so update/delete have identical delayed visibility. Mutations are owner-only; there is no draft-reading API. Replay keys are scoped to owner, payload hash and method/path; responses and mutations commit together, and expired records are pruned during writes. Shard count persists in metadata so restart cannot silently change lookup placement.

## Geography
Implement standard interleaved longitude/latitude base32 geohash. Start at precision 6/5/5/4/4 for 500/1000/2000/5000/20000 meters. A conservative spherical bounding box determines every intersecting grid cell, including neighboring cells. Longitude intervals split across ±180; a circle touching a pole covers every longitude. If more than 4096 grid cells are needed, lower precision until bounded. This avoids the false completeness assumption of a fixed 3×3 grid at high latitude. Prefix index candidates are deduplicated, hydrated and filtered by haversine distance (mean earth radius 6,371,008.8m, 1 micrometer numeric tolerance); distance and ID determine stable order. This is spherical distance, not road distance or an ellipsoidal geodesic.

Indexes are hash partitioned by cell into configurable logical shards. The local SQLite backend keeps these partitions in one database; no claim of physically distributed shards. Read replicas are preferred over physical sharding per the chapter. Quadtree adapts to uneven density but requires tree rebuild/neighbor traversal; S2 spherical cells better handle polar distortion but require an additional geometry backend.

## Network roles
Primary HTTP process owns writes and snapshot publication. Read-only replica processes pull an authenticated JSON snapshot over HTTP into independent SQLite files, atomically install it and index it. A replica continues serving its last complete version when primary is unavailable; health shows snapshot day/version. Poll interval controls staleness. Snapshot protocol has a lineage ID and monotonic version; foreign lineage or rollback is rejected. This is full-snapshot replication, not a MySQL/PostgreSQL WAL replica. Replica export contains public businesses only, excluding owner tokens, drafts and replay records.

A gateway routes public reads to a configured region's replica list, round-robin, retrying transport failures/5xx. It never crosses configured region boundaries and never retries writes. All results of one query come from one replica; versions can differ between replicas. Cursor version conflict is exposed, not silently retried. Admin/owner access uses constant-time Bearer token comparison. Tokens are loaded from a local JSON configuration and never echoed. HTTP request size and cache size are bounded. Replica/gateway are read-only.

## Extensions and limits
Opening windows are UTC weekday/start-minute/end-minute intervals; overnight windows must be split across days. Paging uses a query fingerprint, version and offset; cursors are validated rather than trusted for authorization. No precise-location persistence or HTTP access logs; aggregate benchmark timings only. Production needs TLS, real authentication, owner proof, region-local data stores, incremental replication, health-aware service discovery, monitoring, backups, HA and physical partition placement. Synthetic local measurements establish neither geographic deployment nor book-scale QPS.

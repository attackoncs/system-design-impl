# 设计：附近商家服务（第17章）

## 模块职责

`geo.py` 负责球面距离和有界 geohash 覆盖；`models.py` 负责规范化商家记录、ID、
查询和游标校验；`cache.py` 负责缓存隔离、有界保留和并发加载；`store.py` 协调
SQLite 事务、所有者写入、版本读取和快照安装；`publisher.py` 管理每日发布循环；
`http.py` 实现有界网络传输、鉴权接口、区域路由和副本轮询，`cli.py` 负责资源生命周期。

仍兼容从 store 导入 Cache、Error、canonical 和商家校验函数。
Store 和缓存本身不启动线程，主服务／副本 CLI 才启动各自的后台任务。

## 存储与发布

SQLite WAL 保留五张表：草稿 `drafts`（ID、owner、规范 JSON、墓碑）、公开记录
`public`、复合主键为 `(precision, cell, shard, id)` 的 `geo`、元数据 `meta`、
幂等结果 `replay`。每次操作独立持有连接，以显式读事务或 `BEGIN IMMEDIATE` 写事务执行，
异常回滚并关闭连接。初始化关闭连接，对 WAL 忙等待采用有界重试；逻辑分片数持久化。
旧数据库保留原表和已发布版本，只补草稿修订号／内容哈希等元数据。
草稿修订号由 SQLite 触发器更新，维护工具直接写草稿也会纳入发布检查。

发布先在一致读事务中获取草稿和当前版本，在写事务外生成规范 JSON、六层 geohash
前缀索引和内容哈希。随后开启写事务，核对版本、草稿修订号和目标 UTC 日期；
源数据变化会重试，连续三次竞争后返回可重试503，避免发布过期构建结果。
最终事务统一替换公开记录／索引并推进版本。构建或安装失败保留旧完整版本。
批量安装仍占用 SQLite 写事务，构建需要与数据量成比例的内存，不能称为增量或无成本切换。

已有 WAL 读事务在结束前继续看到旧的完整版本。公开搜索／详情不等待同一个 Store 内
已在运行的发布任务，可继续读取旧版本；每个响应的元数据、候选和商家对象都绑定同一个读事务。
没有发布任务占用时，读请求仍可按需触发到期发布。进程内锁减少同一个 Store 的重复构建，
数据库中的版本／修订号检查负责防止其他 Store 或进程覆盖更新。

主服务 CLI 在 HTTP 绑定成功后启动 `DailyPublisher`，不依赖流量检查 UTC 日期；
`--publication-interval` 指定检查间隔，默认1秒。新一天首次写入先发布昨日草稿，
接受变更前再在写事务中核对日期；若恰好发生日期跳转则返回可重试错误。
管理员强制发布会有意提前公开当前草稿。仅使用 Store 库时保留按需发布；需要空闲时发布的
调用方应显式启动 DailyPublisher。关闭时唤醒等待并回收进行中的构建；后台失败保留旧版本，
记录通用错误并在下次检查重试。该机制实现次日最终可见，不承诺午夜瞬间完成构建和复制。

商家只能由所有者修改，没有读取草稿接口。幂等键按 owner 隔离，并绑定方法、ID和规范化正文；
响应与变更在同一事务提交。记录7天后过期，在后续写入清理，因此过期键再次使用可能创建新商家。
公开详情、更新和删除统一遵循延迟可见的版本语义。

## 缓存与查询

候选缓存键为 lineage、version、precision、cell；详情缓存键为 lineage、version、ID，
精确用户坐标不作缓存键。旧条目无法混入新版本，通过 TTL／LRU 回收。
缓存为进程内实现，按条目数设置容量，使用单调时钟计算 TTL。
固定64个可重入锁条带合并同键冷加载，不创建无限增长的锁表；碰到同一条带的不同冷键仍可能等待。
全局 LRU 锁只保护查找、计数和插入，加载器在锁外执行，热命中无需等待加载锁。
TTL 从加载成功后起算；加载异常不污染缓存。通用 Cache 对加载器提供和返回的可变值深拷贝，
容量设0时不保留条目。Store 的详情缓存改用不可变规范 JSON 文本，详情／搜索取得后
解析为独立字典，避免每次冷加载重复深拷贝字典，同时防止修改嵌套 hours 影响后续读取。

搜索先合并格子中的 ID，再读取详情。首次详情缓存缺失时，按每批256个 ID批量取候选正文，
请求内的 hydration 映射同样保留原始 JSON 文本，避免每条记录单独发 SQL。
记录解析为独立对象后按类别、营业时间、球面距离过滤，按距离和ID排序。
分页从排序结果切片，但 total 的计算仍要求处理全部候选；密集格子超过详情缓存容量时仍可能抖动。
缓存收益需要按实际负载测量，不能因为加入缓存就假定性能提升。

## 地理计算

标准经纬度交错 base32 geohash 的起始精度为6/5/5/4/4，分别对应
500/1000/2000/5000/20000米。采用原书精度表和最后500m示例；缓存段将500m与5km
对应长度写反的文字不作为实现依据。保守球面边界框枚举全部相交格子，经度跨越±180时拆分，
触及极点时覆盖全部经度。超过4096个格子则降低精度，避免高纬度固定3×3邻居遗漏。

最后用稳定的大圆 `atan2` 公式过滤，地球平均半径6,371,008.8米，边界容差1微米。
该公式在近对跖点仍保持稳定，对两个输入位置均作校验。独立单位向量叉积／点积距离参考和
按距离／方位生成的覆盖用例验证极点、日期变更线、半径边界和随机位置。
结果属于球面距离，不代表道路距离或椭球大地测量距离。

索引按格子哈希为可配置逻辑分片，实际仍在同一个 SQLite 文件中。
本实现按章节最终选择使用 geohash；Quadtree 和 S2 是书中对比的替代方案，
不要求同时安装三种索引。物理分片或其他索引后端仍可后续扩展。

## 网络角色与资源管理

主服务负责所有者写入和发布。副本通过带鉴权 HTTP 获取完整 JSON 快照，在自己的
SQLite 文件中准备索引并原子安装；首次有效快照到达前保持未就绪，之后主服务不可用仍保留
最近的完整版本。协议校验 lineage、日期、版本和商家记录，拒绝异源、版本／日期回退，以及
相同版本日期下不同内容的快照；重复的同内容快照不重新安装。内容哈希确保同一个缓存版本键
始终指向不可变数据。导出只有公开商家，不含草稿、owner凭据或幂等记录。

网关按区域独立轮询副本，仅支持公开读路径。准入和全部副本尝试共享一个总期限，
每次尝试获得剩余时间的一部分。默认限制32个在途读取；底层操作真正退出后才释放容量。
网络错误、3xx、5xx或非法响应可尝试下一个配置副本；4xx（含游标冲突）直接返回。
不跨区域切换。一次响应来自一个副本，不同副本可能有版本差异。

出站使用直连 HTTP／HTTPS，HTTPS 保留正常证书校验；不跟随重定向，不读取环境代理，
防止复制凭据被发送到跳转目标。快照正文上限128MiB、公开响应16MiB；拒绝重复 JSON 字段和
非有限数值。自有期限线程取消慢响应头／正文读取并在退出时回收。复制任务只有一个轮询线程，
关闭时设置取消信号、中断进行中的网络读取并等待线程退出。

入站默认限制32个处理线程，设置有界等待队列、套接字超时和总套接字期限（默认10秒）；
超载直接503，不再创建处理线程。关闭会取消活跃套接字工作并回收处理线程／期限线程。
请求拒绝重复头／查询参数、Transfer-Encoding、未知参数和不应出现的正文；
所有者／管理员／复制鉴权先于业务正文读取。写入正文限制64KiB。
Bearer 通过固定长度哈希／常量时间比较校验，不回显凭据；副本和网关拒绝写入。

网络期限无法强行中断操作系统 DNS 解析、SQLite 操作或任意 CPU 工作。
这些工作结束前仍占用容量，关闭也可能等待。此处承诺有界准入，不承诺所有系统调用都有硬期限。

## 校验、隐私与生产边界

营业窗口采用 UTC 星期／起始分钟／结束分钟；跨午夜拆为多天。查询／游标校验拒绝
非法整数、冒充整数的布尔值、重复游标字段、非有限坐标和转换到 UTC 后超范围的时间。
游标绑定完整查询、lineage和版本，变化返回409；它是偏移令牌，不是签名凭据或鉴权依据。

精确用户查询坐标不持久化、不写访问日志；公开商家坐标按业务要求存储。
区域路由配置本身不能证明满足法律中的数据驻留要求。生产部署仍需 TLS 终止、真实身份与
商家所有权证明、实际区域本地部署和隐私控制、按测量决定是否引入 Redis、增量／数据库复制、
服务发现、监控、备份、写主故障切换和物理分区部署。
本地合成实验不能证明云高可用或书中2亿商家／5000搜索QPS。
具体证据见[章节审查记录](chapter17-review.md)和[验证报告](../benchmarks/results.md)。

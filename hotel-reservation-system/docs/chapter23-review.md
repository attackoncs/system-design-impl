# 第23章核对：酒店预订系统

核对日期2026-10-26（Asia/Shanghai），依据
[《System Design Interview.md》](<../../System Design Interview.md>)10507–11226行。
采用标准库、独立HTTP网关/酒店分片/任务worker和模拟支付账本的有界参考。

## 原书映射

| 原书内容 | 当前可执行实现 | 范围/未完成部分 |
| --- | --- | --- |
| 酒店/房型详情和员工管理 | 鉴权CRUD、软删除/显式恢复、房型详情 | 提供HTTP API，没有完整Web/app员工界面或每酒店员工ACL |
| 按日期寻找可用房型 | 酒店级active房型、全住期/数量筛选、每日房型库存查询 | 最多100房型/30晚，报价是参考值，不是库存锁定 |
| 预订房型而非房号 | hotel/room-type/day库存、入住后房号分配不在范围 | 没有房号分配或酒店搜索，符合章节收窄范围 |
| 每天不同价格 | 显式每日价格、expected_total事务复核、订单每晚价格快照 | USD美分，无税费/汇率/需求预测定价算法 |
| 未来两年库存与每日补齐 | 持久策略、默认730天、UTC日历滚动、后台补缺日期 | 显式配置默认值，维护有预算/间隔，不保证截止秒完成 |
| 多夜原子预订/取消 | 库存、订单、价格、支付意图同分片事务；取消只释放一次 | SQLite每片单写者，未实现PostgreSQL/MySQL行锁 |
| 10%超售 | capacity+floor(capacity*overbook/100)，待付款也占库存 | overbook可配置0..10，不能通过改策略压低到现占用以下 |
| 幂等防双击/网络重试 | 用户+酒店+key、规范指纹、确定ID、重放当前订单 | 新key代表新订单；回执/身份没有自动GC |
| 悲观锁/OCC/数据库约束取舍 | BEGIN IMMEDIATE、条件增减和CHECK的组合 | 选择约束方案；可观察version不是OCC重试算法，不冒充三种都实现 |
| 登录用户订单历史/详情 | 酒店范围分页、本人读/取消，管理员可查看/取消 | 无跨分片全局用户索引；管理员不直接以任意guest身份新建订单 |
| 付款后确认、拒付、退款 | 模拟账本、冻结意图/回执、持久任务、租约隔离和补偿 | 只模拟支付，不连接真实银行或供应商 |
| 结果未知和服务故障 | 超时保留任务、同operation重试、取消/过期后成功则补偿退款 | 最终一致；不把超时当拒付，无跨账本强原子事务 |
| 按hotel_id分片 | 两个独立DB/HTTP服务，持久拓扑校验和网关路由 | 固定分片，单热点酒店仍争用同一writer，无在线扩分片 |
| 酒店/库存cache | 1秒TTL/128项、持久revision同快照、冷加载合并和值隔离 | 进程内缓存，不是Redis/CDC；数据库始终复核预订 |
| 网关/内部服务 | 显式method/path/query、角色鉴权、受保护任务及事件API | 无CDN、VPN、gRPC、生产分布式限流或多地域部署 |
| 跨服务一致性 | 订单库存同库ACID，模拟支付独立账本及Saga补偿 | 未实现2PC；本地模拟不证明真实资金exactly-once |
| 规模和高可用 | 有界HTTP并发/期限、重启/真实进程故障/并发验证 | 无分片/账本复制和自动failover，未验收5000酒店/百万房间 |

## 工程修复与并发边界

Store保留门面，schema/catalog/bookings/saga/cache及payment_contracts/transport/routes/worker
拆分职责。可变输入在writer等待前冻结，fresh事务在writer后统一采样时间；幂等重放仍先于
新订单日期校验，因此旧key不会因入住日已过而创建新订单。全住期库存变更、价格快照和支付
意图仍原子提交；缺失待释放夜晚时失败关闭，不悄悄把不完整库存当作已返还。

catalog/availability把revision、active状态与内容固定在同一读快照；新Cache固定条带合并
冷加载，JSON编解码不占全局LRU锁。hotel-wide可用查询也读同一快照，不能把多个日期/房型
的前后版本拼在一起。报价仅供参考，最终写入仍根据约束和实时价格判断。

日历策略只补缺日，不覆盖人工日价、reserved或订单快照。日期行在写锁外准备，每策略短事务
复查generation/version/cursor、active和UTC日，默认每轮32策略/4096日期，最多128/8192。
持久cursor支持重启续跑，完全相同PUT不重置进度。删除重建策略使用不复用generation，修复
旧roller把旧价格发布到新策略的ABA竞态。缩短horizon或删除策略不删除既有库存；旧日期仍需
单独保留策略，参考实现没有自动数据清理。

支付/任务契约严格验证金额类型、action/booking/operation/币种/method与持久意图；坏回执
不能利用bool等同整数来结算。claim先处理未首尝试却已过期的订单，避免首次无谓扣款。
回调只在当前租约token仍持有时接受，取消/过期后的成功转为持久退款。退款完成回执可在
模拟故障开关开启时重放；错误是结果未知则继续重试，不伪造decline。

Worker单轮默认10秒RPC总预算，自有线程/cancel和close排空；legacy自定义execute(job)
仍兼容，其阻塞工作由调用方自己控制。网络/回调错误只持久化通用信息，health/status有可见
失败/有限输出。CLI先bind再启动calendar维护，关闭排空HTTP和后台已接受任务。

HTTP默认32个处理名额、128 backlog、10秒绝对I/O、1MiB请求/4MiB响应。鉴权先于正文，
拒绝重复/歧义framing、重复JSON字段与非有限数；网关只转发明确的公共路由，写入不盲目重试。
RPC直连不走环境代理/重定向，HTTPS正常校验证书。socket期限无法强杀DNS/SQL/CPU，
名额保留至实际退出；未把线程上限等同生产吞吐保证。

## 执行证据和图分析

最终 **99项测试通过（22.901秒），无跳过/ResourceWarning**；修改前基线13项18.699秒。
包含原9项状态/库存及4项独立网络、新20项Store/cache、14项支付、12项worker、17项真实
HTTP/RPC、7项CLI/维护、16项日历/酒店房型查询。受控异常和真实进程故障分别标明。

六进程原demo确认/退款成功，hold到确认183.85ms、2次模拟操作、库存恢复11；新
[chapter_demo](../examples/chapter_demo.py)验证后台730天×2房型、管理员策略权限、数量筛选、
人工12000日价、44000订单及补偿完成。[原始功能结果](../benchmarks/features-2026-10-26.json)。

热点酒店100请求/16客户端测量接受22/拒绝78，两晚reserved均22、模拟唯一charge22；
全部订单确认。最终结果和小样本限制见[报告](../benchmarks/results.md)与
[原始测量](../benchmarks/review-2026-10-26.json)。历史Oct20证据保留历史日期。

code-review-graph完成最小上下文、增量刷新、调用方和影响分析；最后刷新21文件无构建错误。
6个既有核心文件为72直接改动节点、16受影响节点、额外4文件，2122调用未解析、边有截断。
SimulatedLedger.execute查到5个绑定调用点、跨2个测试节点；动态HTTP分派可能漏边。
新未跟踪calendar_policy.py明确未索引，不能把空图结果当作没有功能/测试的证明；这些新模块
已用源码、独立复核和实际执行补核。此前其他章节脏改动仍在全库图上下文中。

## 仍未实现的生产能力

真实支付、酒店当地时区/取消罚金/税费/多币种、员工按酒店授权及完整前端、
跨分片用户索引、Redis/CDC、真实行锁或OCC后端、复制/共识/在线扩分片/自动故障转移、
CDN/TLS/分布式限流、隐私/回执GC、备份恢复与持续大规模/掉电验收均为后续。
SQLite本地磁盘进程恢复不能代替机器/磁盘丢失或真实供应商投递的验证。

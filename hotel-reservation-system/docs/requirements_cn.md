# 需求：酒店预订系统

来源：[System Design Interview.md](<../../System Design Interview.md>)第23章10507–11226行。
核对日期2026-10-26。最终证据见[验证报告](../benchmarks/results.md)，覆盖与缺口见
[章节记录](chapter23-review.md)。

1. 酒店/房型详情与授权增改、软删除；按房型预订，不分配具体房号，不实现酒店搜索。
2. 支持房型可用量及酒店内跨房型日期/数量查询；日历须完整、日价明确，源类型数量有界。
3. 可显式启用持久滚动日历，最长未来730个UTC日；只补空日、不改既有价格/占用，发布检查
   generation/version/cursor防ABA。停用/缩短策略保留旧库存。
4. 日期[入住,离店)，1..30晚/1..10间、未来730个UTC日；任意缺日或不足使多夜事务全回滚。
5. 占用含pending和confirmed，始终≤capacity+floor(capacity*overbook/100)，超售0..10；
   管理员不能把限额降至当前占用以下。
6. 使用USD整数美分，保存不可变订单日价；writer内再次核对expected_total，调价需重新接受报价。
7. hotel/guest/request_key+冻结内容幂等；重放返回现有当前状态，不复活取消/过期hold。身份来自
   凭据，他人和缺失订单同样404。
8. 库存、订单、charge意图同分片事务提交；未过期全额模拟支付才确认。明确拒付释放，未知结果
   持续可重试，晚到成功必须退款补偿。
9. 校验job/receipt/金额/操作身份并隔离旧lease；取消/退款幂等、过期清理有界，不静默丢弃资金
   不确定任务。全部支付为模拟，不操作真实资金。
10. 一致快照/revision参考缓存、冷加载合并、结果隔离、有索引的有限维护；写入最终约束仍在DB。
11. 有界HTTP准入、framing/JSON/字节和I/O预算；网关仅转发显式公共路由，保持身份，不盲目
   重试写入。handler及后台工作拥有启动、可观测重试、关闭排空。
12. 集成证据使用独立HTTP进程和真实本地磁盘，受控故障/provider明确标注，不将本机结果当作
   生产规模、银行正确性或复制持久性。

生产扩展：复制/HA、在线扩分片、分布式缓存/CDC、全局用户索引、真实支付、酒店当地政策/
税费/币种、员工租户ACL、TLS/配额、隐私保留、灾难恢复及原书5000酒店/100万房间持续验收。

# 第28章数字钱包：快照加尾部恢复与增量日志（2026-11-09）

本轮重读《System Design Interview.md》第28章Snapshot一节（Figure 22）：快照保存后，状态机“读取快照、核实停止位置，从那里继续处理”，无需每次从头重放。旧实现虽有快照，但`_rebuild`先完整重放全部历史、再重放快照前缀做比对，有快照时反而约为无快照的两倍工作量。本轮只改数字钱包，补齐这一缺口并修复两处随历史增长的效率缺陷。

## 发现与修改

1. **快照不加速恢复（原书缺口）。** 重启、快照发布和`?at=n`历史查询均改为“快照＋尾部”：校验快照校验和与结构，确认日志在快照序号处仍有同一链头且该行自校验通过，只从该链头校验尾部哈希链并重放尾部。快照超前于日志、来自其他日志或校验和错误时中止恢复。快照由上一快照加尾部增量生成；早于快照的`?at=n`或快照不可用时退回从创世事件起的校验重放，历史读取仍可用。
2. **完整历史校验移至审计。** `audit`在快照发布锁内校验整条链、从创世重放，同时比对投影与快照在其序号处的状态/链头；重新计算校验和的伪造快照会让`matches=false`。响应字段不变，协调者审计契约无需修改。这是明确取舍：快速恢复信任已校验发布的快照，前缀篡改由审计发现。
3. **重放为平方级。** `reduce_event`每个事件深拷贝整个状态，而每笔转账都增加参与者记录，重放为O(事件×参与者)。新增原地`apply_event`/`apply_events`供持有状态的循环使用，`reduce_event`保持纯函数（拷贝后调用前者）；与协调者投影已采用的“一次拷贝、原地折叠”一致。
4. **每次日志同步扫描整个协调日志。** `Journal._sync`每次加载并重新哈希全部记录。现在启动时完整校验一次，之后只校验上次已校验链头后的新行，并固定不可变`LogView`前缀；各副本只读取其报告位置之后的后缀，发送前与已校验链头重新相连。本轮之后追加的行不在视图内，仍不会被误标为已提交。
5. **测试时间假设。** `test_same_request_can_wait_pending_timeout_terminal_and_restart`在WSL `/mnt/e`上修改前即稳定失败：六个复制TCC步骤约2.5秒，超出单次`wait_ms=2000`上限（逻辑正确，转账最终SUCCEEDED）。改为客户端重复发起同一有界长轮询，仍走`wait_ms`路径。

改动：[common.verify](../src/digital_wallet/common.py)支持链段校验；[projection](../src/digital_wallet/projection.py)；[shard](../src/digital_wallet/shard.py)；[journal](../src/digital_wallet/journal.py)；新增[11项回归](../tests/test_snapshot_recovery.py)与[基准工具](../tools/snapshot_benchmark.py)。无新增依赖，HTTP/RPC契约不变。

## 已复现并修复的问题

1. **总额相等掩盖错片/错账户。** 默认三个账户各10000，无任何转账时，将两片完整view/audit响应交换，旧审计仍返回matches=true；等额替换账户也能通过。现在先校验响应结构与严格类型，再核对分片ID和按配置路由得到的准确账户集合。身份/分布差异返回matches=false；缺字段、布尔值伪装整数、负数或超供应金额等非法回执返回502，不算作客户端输入错误。
2. **累计余额误用初始余额上限。** 初始余额`10**12`的账户合法收取100分后，旧公共查询把`10**12+100`判成无效回执。现在累计可用/冻结金额按配置总供应量校验，保留严格整数和非负限制。单户`opening≤10**12`、单次`amount≤10**8`均不变，总供应最多`100×10**12`。

两处修复分别落在[audit.py](../src/digital_wallet/audit.py)与[Coordinator.balance](../src/digital_wallet/coordinator.py)；新增[5项回归测试](../tests/test_audit_reliability.py)先在旧实现复现，再验证修复。不增加依赖或通用框架。另以真实SQLite适配器逐步检查COMMIT的7个状态和CANCEL的6个状态，正常冻结、释放与在途阶段均能通过审计。

## 主要修改

- contracts/projection/coordinator_projection/runtime/audit/routes/transport/server_runtime分层；原导入路径兼容，无跨章节运行时依赖。测试/示例/工具统一格式。

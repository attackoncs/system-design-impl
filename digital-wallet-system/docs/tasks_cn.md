# Tasks: Digital Wallet

来源：根目录 `System Design Interview.md` 第 28 章，章节起始行 14171。

状态：参考实现完成；54项测试及7进程HTTP演示/实测通过。全部合成余额；固定协调者日志多数派及持久epoch隔离已验证，未实现自动选主、账户分片复制或协调者原盘丢失恢复，百万TPS/四个九未证明。

## 范围

双钱包余额转账、事务正确性与历史可重演；不含汇率，百万 TPS 与四个九为设计目标。

## 实施任务

- [x] T1. 编写需求/设计，定义账户、金额整数单位、转账命令、事件日志、余额及守恒不变量。
- [x] T2. 实现单分区原子转账、余额不足拒绝、幂等命令与并发扣款保护。
- [x] T3. 实现按账户分片及跨分区转账；比较 2PC、TCC 和 Saga，选定策略后明确恢复状态。
- [x] T4. 实现追加事件日志、确定性重演、CQRS 余额读取及历史余额重建。
- [x] T5. 实现快照、文件日志/状态持久化、校验和与重启恢复，验证重演不会再扣款。
- [x] T6. 实现固定协调者epoch隔离、三节点真实HTTP日志多数派及原盘恢复；自动选主/账户副本另属未实现扩展。
- [x] T7. 实现跨分片 pending/confirm/cancel 的恢复、审计追踪和内部对账；不连接真实资金。
- [x] T8. 验证并发/重复转账、分区/崩溃、部分提交、重演一致性及余额守恒，实测并说明百万 TPS 未证明。
- [x] T9. 提供可运行示例、英/中文 README、设计取舍及实际测试/压测报告，更新根目录状态；未验证的生产规模保持明确。

## 验收门槛

- 正确性、持久化重启、幂等和故障路径有可重复测试。
- 分布式能力须用实际独立进程/网络验证，模拟实现单独标注。
- 外部云服务/供应商使用可替换适配器；未配置凭据时不能宣称真实服务已验证。
- 原书规模和可用性数字是设计目标，不由本机测试直接证明。
- 仅在用户要求后提交；docs 下 requirements.md/tasks.md 延续不提交的约定。

# 第28章数字钱包需求

来源：根目录《System Design Interview.md》第28章。仅实现钱包到钱包的合成余额转账；百万TPS、99.99%可用性为原书目标，不能从本机测试推导。

- 金额为USD整数美分，静态预置账户及合成初始余额，不连接真实支付渠道。
- 同分片原子转账、余额不足拒绝、全局转账ID幂等与内容冲突检查；并发扣款不透支。
- SHA256账户分片，跨分片选用TCC，保留待处理、提交/取消决定、冻结与在途资金，支持崩溃后继续。
- 追加且有校验和的事件日志、确定性重放、独立读投影、分片序号历史查询、快照加尾部事件恢复。
- 固定协调者的三节点HTTP日志多数派接口及持久epoch隔离；不宣称自动选主、账户副本HA或原盘丢失恢复。
- 取消墓碑阻止迟到Try；提交决定后不可取消；未知响应不自动释放冻结、不更换付款身份。
- 查询参与者状态恢复、连续失败人工重试、日志/投影/参与者对账及包含在途金额的资金守恒。
- 独立进程验证并发、网络不可用、少数接收、部分提交、重启和重放；提供双语文档、演示、实测报告。

明确不含存取款、外汇、手续费、拒付、真实银行对账或生产身份管理。各分片历史序号不是全局时间戳，TCC中间状态可见。

- 有界完成通知：转账POST/GET支持wait_ms=0..2000，等待不持资金锁，超时保持原状态；最多8等待者。
- 输入/回执冻结校验、同一快照余额与序号、并发快照安全发布；日志复制并行但追加/同步串行，提交仅覆盖确认前缀。
- 有限连接/线程/响应、端到端I/O截止时间、取消排空、严格JSON和HTTP契约；状态缓存可重建而非资金真相。

未覆盖：Raft选主与账户事件副本、权威丢盘提升、独立部署CQRS读副本、快照跳过扫描/裁剪及百万TPS/四个九证明。

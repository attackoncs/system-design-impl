## 正确性与故障

在原8本地/6七进程测试上增加40项：5配置/生命周期、7完成等待/容量、6HTTP契约、17一致性/并发、4传输、1七进程通知/重启。原扣款竞争、取消墓碑、部分COMMIT、丢响应、死信、少数派接受、原盘恢复及epoch隔离保持通过。新增覆盖：

- 在协调者锁/SQLite写锁等待前冻结调用方输入；错意图、金额/类型、角色、空回执不授权下一资金步骤。
- 当前余额、序号、投影来自同一SQLite读快照；并发快照/资金写入发布完整文件且重建一致。Windows同时替换曾复现WinError5，已用独立发布锁、唯一临时文件和有限重试修复。
- 日志三副本并行复制，追加/sync共用锁，仅将已确认快照范围提交；原盘未提交意图在空闲worker恢复；错误副本count/ACK拒绝，异常适配器仍排空所有已接受任务后释放写锁。
- 已提交协调事实缓存只应用后缀，返回值不与缓存共享；轮转推进、错误参与者角色和已拒绝结果可审计。
- 完成等待通知不持资金锁，超时/取消保留PENDING/冻结，最多8等待者；重启后原ID可读终态。慢连接截止时间与连接容量回收，重复/非有限JSON、歧义HTTP、重复凭据/查询、额外管理字段均拒绝。
- RPC绕过环境代理，不跟随重定向；滴流不能延长总I/O截止时间，取消能唤醒Windows超时模式读取。

## 重复执行

```powershell
python -m unittest discover -s tests -v

```

最终完整测试：**14项通过，56.008秒**。8项本地状态/日志测试，6项HTTP测试每项启动七个独立进程：固定协调者、worker、两个账户分片、三个协调日志副本。六个独立数据库文件不跨服务共享，但均位于同一主机。

## 正确性及故障路径

| 路径 | 实际验证 |
|---|---|
| 并发重复请求 | 同一转账ID的12次并发请求只扣款一次；更改内容返回409 |
| 竞争扣款 | 两笔各6000美分争抢10000余额，一笔确认、一笔拒绝，无透支 |
| 提交前异常 | 事件与余额投影一同回滚 |
| 权限与金额 | 其他用户不能支出源账户或读取其余额；拒绝浮点、布尔值、字符串金额及其他币种 |
| 同分片与跨分片 | 本地原子完成；跨分片冻结、提交决定、双方确认及最终完成逐步持久化 |
| 取消及迟到Try | Try被明确拒绝后选择Cancel，资金释放；空取消/取消后迟到Try不能复活资金动作 |
| 部分提交 | 付款方已确认、收款方未确认时500美分在途，钱包总额29500＋在途500＝初始30000 |
| 部分提交后重启 | 重启协调者及两个账户分片，仍识别500在途；继续确认后总余额30000，不重复扣款 |
| 提交后丢响应 | 源Try提交但返回503，仍只冻结一次；后续从参与者状态恢复 |
| 网络不可用及人工恢复 | 目标分片不可用使连续失败达到5次，保持PENDING和冻结；恢复分片、人工重试后完成 |
| 真实日志多数派 | 三副本停一个仍可完成；仅剩一个时停止受理/推进 |
| 少数已接受的意图 | 状态探测正常但两个副本拒绝追加，只有一个收到新意图；503后重启原盘协调者，恢复多数派并完成原ID |
| 副本重新加入 | 补齐落后副本后三者序号和链头一致 |
| epoch隔离 | 手工提升全部副本和分片epoch，旧协调者无法获多数派、旧分片写入409；原盘新epoch可继续 |
| 快照/尾部/历史 | 快照后产生新事件，重启重建正确；按序号查询初始/冻结历史；重放不触发网络扣款 |
| 损坏与投影漂移 | 拒绝修改事件，篡改快照/事件校验失败；有效日志可重建损坏的读投影 |

第一轮网络测试发现外层HTTP的2秒预算与嵌套调用相同，停机路径会在协调者响应前超时。已将外层预算改为10秒，本机副本/分片调用分别限制0.4/0.5秒，随后完整测试通过。超时始终按不确定结果处理，未通过将未决转账判失败来规避测试。
